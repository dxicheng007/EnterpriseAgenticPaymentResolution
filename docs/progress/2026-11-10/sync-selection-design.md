# P2 Phase A: bounded read-only synchronization selection

Status: design candidate, 2026-11-10. This document implements the Phase A recommendation in [the scope audit](sync-coordination-scope-audit.md); it authorizes no implementation. It owns only this document. No source, migration, Git, database, test, provider or model operation was performed. Fresh design review and reconciliation with final P1 acceptance precede an implementation plan.

## Intent and accepted boundaries

Given genuine committed subjects and already captured API financial input, return a reproducible proposal for each customer's earliest eligible financial group, or the exact blocker. Keep raw unknown work visible while independently mapped customers can have proposals. Discover later captured prerequisites across approved API streams through the accepted compiler's typed metadata, then reclassify the complete coupled group. A proposal is neither permission to apply nor evidence that anything was applied.

Normative anchors are PRD §§10–13, especially [durable inbox and checkpoints](../../../prdv2.md#durable-inbox-and-checkpoints); [F1, F2, F3 and F5](../../superpowers/plans/2026-11-08-contract-freeze.md); [accepted classification design](../2026-11-08/handoffs/platform-sync-classification-design.md); and [accepted capture contract](../../superpowers/plans/2026-11-09-sync-capture.md). The [apply repair plan](../../superpowers/plans/2026-11-10-sync-apply-repair.md) remains the narrower P1 writer contract. Its storage at `7af5d8ace77a087529c05bada4c8da48f7b4a0d2` is accepted history; Task 2 `7161d6e` is now accepted; final P1 service/type reconciliation still precedes implementation, and this design does not adopt moving Task 3 writer interfaces.

F1 explicitly permits independent mapped accounts to continue when another raw account has a known company/seller but no approved account mapping. This does not resolve that raw account's financial input. Missing/ambiguous seller or unscoped governing change stops source financial application. The distinction is already specified and needs no new skip permission.

The compiler owns mapping, economic equality, financial groups, typed prerequisites and validation. Phase A owns a bounded storage read, trusted routing, selection and an explanatory witness. It does not write outcomes, receipts, heads, pending/quarantine rows, examinations, claims, activity or authority. It does not initialize capture, fetch providers or current semantics, invoke a model, expose HTTP, schedule work, handle CSV or generalize P1. A later writer must independently re-read and revalidate; no Phase A result is an input accepted by the P1 writer.

## Approach and deliberate narrowing

Use a complete, small in-memory corpus from one read-only PostgreSQL snapshot, with overflow sentinels before decoding or classification. This makes negative provider lookup, enrolled-profile completeness and full compiler group membership reviewable without introducing a durable dependency index or another financial interpreter.

An unbounded source scan is rejected: `LIMIT 1000` cannot prove the omitted history harmless. A persistent typed index would support longer histories but requires a separate write, rebuild and coverage contract. Phase A therefore retains a **technical complete-corpus limit** and explicitly returns incomplete coverage beyond it. This is not the steady-state 1,000-input cycle rule and does not remove P1's lifetime restriction. The implementation plan may tighten operational limits; increasing them or adding incremental coverage requires review.

Suggested future paths are only `apps/worker/src/sync/selection.ts` (types, pure routing/selection) and `apps/worker/src/sync/selection-read.ts` (SELECT-only adapter), with `apps/worker/test/sync-selection.test.ts` and `tests/integration/sync-selection.test.ts`. Reuse `dependencies.ts` ordering/topological helpers, existing validated parent reads, `classifyBatch` on its existing subpath, and the already exported `validateSourcePayload`/`MappingError` on `@eapr/compiler/operations`. No compiler, finance, contracts barrel, composition, P1 file, migration or existing fixture changes are proposed. These are candidate paths, not reservations.

## Small internal API

```ts
createSyncSelector({ db }: { db: Pool }): {
  inspect(input: { sourceRef: Id; asOf: IsoInstant }): Promise<SelectionInspectionV1>;
};
```

The caller chooses only a source and explicit evaluation instant. It cannot supply events, profiles, target state, authority labels, cursors, limits, exclusions or a preferred group. The internal service is not a new public read grant. Discover all committed subjects for this source in runtime storage, validate each exact committed import, and bind each selected profile to its own activation ID, bundle/artifact/profile/manifest hashes and baseline vector. A profile merely present in a multi-profile bundle is not enrolled; the exact committed activation/request must select it. Read paused/revoked subjects too so they cannot become falsely unknown; their own proposals are blocked by observed inactive authority. Empty enrollment returns `coverage: { kind: 'incomplete', reason: 'no_committed_subjects', boundedFacts }` with empty proposals, blockers and routes. The bounded catalog observation establishes only that no committed subject was found in this snapshot, not global source completeness.

```ts
type SelectionInspectionV1 = {
  schemaVersion: '1'; sourceRef: Id; asOf: IsoInstant;
  coverage: { kind: 'complete_captured_cut'; witness: SelectionWitness }
    | { kind: 'incomplete'; reason: IncompleteReason; boundedFacts: CutSummary };
  proposals: ProposedGroup[]; // always [] for incomplete coverage
  blockers: SelectionBlocker[];
  routes: RouteObservation[];
};
type ProposedGroup = {
  identity: CommittedAuthorityIdentityV1;
  observedEpoch: number; targetVersion: number; targetSnapshotHash: Hash;
  seed: EventRef; members: EventRef[]; orderedMembers: EventRef[];
  classifierBinding: ClassificationBinding;
  dependencies: DependencyWitness[];
  plan: MutationPlan | null; // null only for accepted all-replay group
  replayOrigins: ReceiptOrigin[]; // validated initial/ongoing origins, never invented
  witnessHash: Hash;
};
```

Names above are internal proposed types, not imports from Task 2. The implementation must reuse finally accepted identity/origin types where available. `IncompleteReason` is a closed union of `limit`, `timeout`, `unsupported_transport`, `uninitialized_capture`, `uncovered_stream`, `unknown_source_binding`, `unsupported_history`, `source_contract_validation`, `no_committed_subjects`. Corrupt persisted canonical/hash/index/foreign-key bindings return a safe `SELECTION_STORAGE_INVALID` failure instead of a partially trustworthy result. Malformed input is `SELECTION_INPUT_INVALID`; database failure is `SELECTION_UNAVAILABLE`. No SQL, raw payload or credentials appear in error text.

A blocker carries its level (`source`, `mapping`, `subject`, or `raw_identity`), fixed code, applicable identity or raw company/seller/account tuple, exact causing `EventRef[]` or incident references, and typed missing keys when available. It never assigns Scope to unmapped raw input. Codes include `source_identity`, `source_semantics`, `schema_mapping`, `unknown_account`, `ambiguous_mapping`, `inactive_authority`, `dependency_missing`, `dependency_invalid`, `dependency_cycle`, `group_limit`, `earlier_hold`, `global_economic_conflict`, and `capture_incident_unresolved`; underlying compiler hold codes remain attached unchanged. Bounds failures are coverage incompleteness, not financial rejection or quarantine.

## One captured cut, finite reads

Check out one runtime client; execute `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY`. All catalog, imports, authority, targets, capture evidence, original associations and prior application history reads use this client/snapshot. No helper may acquire write locks, initialize rows, publish activity, open a second connection or fetch another service. Roll back on error and release the client. Classification runs after the bounded immutable data is detached and the read transaction ends.

Suggested prototype ceilings are 8 committed subjects, 8 lanes, 32 total lane-stream definitions, 1,000 distinct post-baseline deliveries in the union corpus, and 1,000 rows **per evidence family** (pages, inbox memberships, incidents, units, outcomes and original-origin associations). A subject's complete target may contain at most 10,000 financial/metadata records. Allow at most 1 MiB for any canonical value and 16 MiB total canonical input to the inspection. These are engineering admission ceilings, not changes to financial authority. The existing approved invocation limit remains at most 1,000 inputs including prerequisites and repeated occurrences, and 5,000,000 cents per transaction. Enforce the stricter committed/compiler limit, if any.

Read bounded keys/scalars plus `octet_length(canonical_column)` before fetching canonical blobs. Use ordered `LIMIT cap + 1` for each evidence family and each subject target, with indexed source/lane/scope predicates; exact key reads use those previously bounded key sets. Sum checked byte lengths before retrieval. An extra row or oversized value terminates the inspection with zero proposals; never decode only a prefix and claim complete coverage. The aggregate byte limit includes committed bundles and embedded baseline evidence, so a validated helper that loads unbounded blobs must be preceded by these checks. Set local statement timeout to 2 seconds and an application transaction deadline of 5 seconds; cancellation returns incomplete timeout, never an empty successful cut. Query/index feasibility is part of implementation review; timeout prevents an expensive anti-join from becoming an unbounded operation.

The adapter must inspect all source lanes and all committed subjects, not just caller-selected ones. Within bounds it validates:

1. Exact imports, each current authority observation, artifact/profile bindings, each original baseline vector and current target. No newest capture head is substituted for another customer's older baseline.
2. All declared API/semantic streams and lane checkpoints, with exact immutable complete-page, inbox, global-position and canonical-delivery agreement for every retained post-baseline position. Bootstrap identities and baseline membership are validated through the committed import; they are not fabricated as post-baseline inbox entries. Reject CSV-bearing subjects/lanes for the entire inspection.
3. Both directions of membership: pages' exact members equal inbox rows, and no relevant delivery/position/inbox/page is omitted, orphaned, undeclared or beyond its checkpoint. A bounded key scan plus indexed `EXISTS` anti-joins detects extras; it never uses the latest-incident summary as complete evidence. Include **all** retained source incidents under the bound.
4. Historical P1 units, first outcomes, original associations and heads needed to distinguish already acknowledged inputs. Reuse accepted strict decoders and exact key reads. Their finite reference graph must close inside the budgets; unsupported legacy receipt-only history yields incomplete coverage. It does not authorize a guessed application frontier.
5. Global economic/delivery claims for every mapped candidate and replay record, including claims in other scopes. Lookup is by the full accepted typed identity/derived target ID, not selected account alone. A foreign-scope origin or contradictory original association blocks the affected candidate; missing/corrupt origin for existing target economics is storage invalid. No new economic novelty is certified solely by `financial_new`.

For a subject, candidate members must belong to its own validated lane, approved stream and interval `(its baseline, its captured cursor]`. Cross-stream discovery is supported within that lane. Other lanes remain part of source guard/identity evidence. If another lane has relevant later input that is not covered by a subject's own lane, return `uncovered_stream` naming that subject and zero proposals for this inspection; do not silently select the convenient shorter cut or borrow another lane's baseline. Any structural incompleteness produces zero proposals globally. More permissive partial-cut admission is deferred. This restriction concerns incomplete evidence, not a fully evidenced known-account hold or raw unknown account, which can coexist with independent proposals.

The snapshot guarantees consistency **as read**, not freshness at response time or a capture/apply fence. Later capture, pause/revoke or parent writes cannot alter this witness, but can make it stale immediately. No current source high-water or latest provider state is observed. Identical captured state, authority/target observations and `asOf` yield identical ordered output and hashes; wall-clock timing/transaction IDs are not hash inputs.

## Routing without erasing unresolved work

Build an index only from exact selected profiles of validated committed subjects. The routing key is `(sourceRef, companyId, sellerEntityId, sourceAccountId)`. Deduplicate repeated lane memberships by full delivery identity after proving canonical equality; retain every membership in evidence. Different event IDs with the same economics remain distinct classifier inputs. Record exactly one route observation per distinct inspected delivery, plus applicability to each subject's baseline/cut.

- **Known independent:** exactly one committed profile matches all identity components. Route to that subject's pinned artifact/profile and target. A different subject's `UNKNOWN_ACCOUNT` result cannot override this match. Pause/revoke blocks only the matched subject's proposal, without changing its routing to unknown.
- **Known seller, unknown account:** company/seller is established by the complete enrolled catalog, but no profile maps the raw source account. Keep `unknown_account` with raw identity and immutable event reference. It cannot be selected or become a provider. It does not by itself block independent mapped subjects. No global resolved/excluded/ignored outcome is produced.
- **Source-wide identity/governing uncertainty:** missing seller; multiple conflicting approved matches; or governing semantic input without safe account scope blocks source proposals. Preserve actual accepted classifier `sourceBlockers` and causing references. A company/seller not established by the inspected committed source catalog is `unknown_source_binding` incomplete coverage, not a guessed known-seller unknown account or a new scope.

Run source guard checks before removing unrelated customer input. For each subject, applicability means the union of inspected deliveries strictly after that subject's approved baseline for the named stream, with source/stream binding proven and all relevant own-lane coverage present. Input at or before that subject's baseline is baseline evidence, not a post-approval semantic change. For this applicable captured history, use the accepted classifier on the full bounded source corpus with that subject's genuine artifact/profile/target to collect its explicit source blockers; do not interpret foreign-profile holds as global unknowns. Then classify its routed financial and applicable semantic inputs together. Do not let a foreign subject's ordinary identity hold suppress a valid known account.

### Pre-routing source-contract guard

Before account filtering or financial group selection, validate every applicable captured event against **each distinct approved source-contract binding** consuming its feed/resource. Include known accounts, known-seller unknown accounts, paused/revoked subjects' input and already acknowledged post-baseline input. Do not discard these checks based on the eventual route or outcome. Subject applicability remains its exact source/company/stream and post-baseline interval defined above. A binding is `{sourceRef, companyId, streamId, resource, sourceContractHash}` from the validated artifact's capture definition, exact `SourceContract` and accepted `sourceContractHashes`; its consumers are the sorted exact committed identities/artifact hashes using that binding. Contracts differing between approved artifacts are checked separately, not assumed equivalent. This is a bounded catalog join, not identity enrollment or payload interpretation.

First check resource, stream assignment, kind and declared schema version against that binding using the same envelope predicates as accepted `materialize`. Then call the **existing** `validateSourcePayload(contract, event)` from the already exported `@eapr/compiler/operations` subpath on the original immutable event. It validates undeclared/required fields, types/ranges/enums, formats and payload-to-envelope identity agreement. It takes no profile or approved Scope, so the guard does not pretend that an unknown account is enrolled. No local copy of its field traversal, decimal/date parsing, mapping, economic comparison or financial interpreter is permitted. `planBatch`, `classifyBatch`, their ordinary holds and `sourceBlockers` outputs stay byte-for-byte compatible; no compiler edit or new export is needed for this seam.

Record one `SourceContractObservation` per distinct applicable `(event, binding)`, referencing the full sorted consumer set. Its closed result is `passed`, `mapping_blocked` or `unexamined`. For `mapping_blocked`, retain the fixed selector code `schema_mapping`, the causing `EventRef`, exact binding/consumer references, and one of:

- `origin: 'envelope'`, with deterministic failed fields among `/resource`, `/streamId`, `/kind`, `/schemaVersion` and the approved expected values;
- `origin: 'compiler_payload'`, with the actual `MappingError.code === 'SOURCE_SCHEMA'` and exact `MappingError.path`. This covers undeclared/renamed/missing required fields, changed type/range/enum and payload/envelope identity mismatch. Preserve the actual returned first diagnostic; do not invent unreported paths or parse error message prose.

Each failed binding propagates a mapping-level blocker to **every applicable consumer of that exact binding**, whether the causing event maps to A, another account, or no account. Those subjects receive no proposal in this inspection, even for otherwise valid work; this is the conservative Phase A admission rule for a subject that depends on a failed mapping. A separately approved binding on a genuinely different unaffected feed/resource remains eligible if its own checks and all source guards pass. A different contract for the same feed/resource is eligible only after its own independent validation and existing schema/semantic authority checks, never because another version passed. If a declared resource/stream cannot be assigned to a safe affected binding/consumer set, return incomplete `source_contract_validation`, zero proposals; do not guess the blast radius. Source-wide identity/semantic blockers still override mapping-level eligibility.

`validateSourcePayload` is fail-fast and can return `MONEY_FORMAT`, `MONEY_SCALE`, `MONEY_RANGE` or `SOURCE_DATE` before reaching later structural fields. Such a result does **not** prove complete structural validity. Retain its exact compiler code/path as `unexamined`, return incomplete `source_contract_validation` and zero proposals globally. Do not convert it into a newly defined mapping-wide financial rejection, quarantine, or a successful structure check. An unexpected exception, unavailable seam or missing proof that the imported implementation is the accepted validator likewise cannot produce a complete cut; unexpected storage corruption keeps its existing storage-error treatment. A future compiler-owned exhaustive structural seam would need separate ownership/review while preserving existing planner outputs; it is not introduced here. Ordinary mapped financial failures reached after a passed source-contract guard remain their accepted scoped/group holds.

Retain successful observations as well as failed/unexamined ones, so a witness proves that an unknown-account payload was actually checked. For an incomplete result, `boundedFacts.sourceContractObservations` retains the bounded checks completed before stopping, including the exact unexamined cause, with `sourceContractChecksComplete: false`; it is not a complete selection witness. Complete cuts require `sourceContractChecksComplete: true` and the full observation set. At most 8 subject bindings can apply to each of the at most 1,000 corpus deliveries; deduplicate equal bindings, bound guard observations to 8,000 and include their bytes in the existing aggregate limit. Overflow is incomplete coverage, not selective omission. No field values or raw error messages are duplicated into this diagnostic witness.

All captured governing history after the subject's baseline participates in classification, including earlier changed revisions followed by an apparently matching revision. A `semantic_observed` result is an unchanged nonfinancial observation only. It supplies no receipt, outcome, financial frontier or approval of a changed revision. Already acknowledged financial inputs may be omitted from pending candidates only after exact historical proof; semantic guard history and unresolved raw input are never dropped for that reason. No private current-semantics fetch occurs, so proposal validity is explicitly limited to captured declared dependencies.

Capture incidents remain immutable evidence. Identity/page conflicts block source proposals pending a separately reviewed resolution contract. A historical gap alone is not proof of a current gap: its accepted contiguous page history may prove complete current coverage. However, existing incident summaries do not retain a full rejected range. If the accepted stored incident fields cannot establish that a particular gap is covered, Phase A reports `capture_incident_unresolved` and offers no affected proposal. Neither a later success nor disappearance from the latest summary clears it. A richer incident-resolution representation is deferred.

## Earliest work and exact typed closure

Use `compareInbox`: stream ID, numeric sequence, event ID. This is deterministic enumeration across independent streams, not a claim of global temporal order. Captured stream positions retain their own meaning. For each subject remove only deliveries proved already acknowledged by accepted historical outcomes for that subject, keeping their validated origin/history references. All other routed financial deliveries are unfinished; equivalent target economics still need replay acknowledgment in a future writer.

Classify the subject's complete bounded unfinished financial corpus together with applicable captured semantic history against its exact target at explicit `asOf`. This deliberate full-corpus pass is essential: the accepted compiler groups both typed dependencies and candidates coupled through **existing allocation edges**, shared funding/invoice capacity and reversals. Do not build groups by event kind or singleton classification. A `not_classified` branch blocks that subject, with its real reason; no absent item is treated as a replay.

Index only `mapped` metadata from this accepted result, including mapped held items. The exact provider key is `(canonical Scope, EconomicIdentity, targetRecordId)`, with relation retained on each consumer edge. `EconomicIdentity` includes source, seller, kind and source record ID. Do not use `Hold.dependencies`, bare record IDs, SQL JSON payload paths, compiler operations, or a new DSL to discover providers. This is a bounded in-memory exact lookup over compiler-owned mapping, not an external query. SQL discovers the complete bounded captured corpus; it never asserts that an envelope or payload field alone proves a usable provider.

Select the earliest unfinished financial item. If it is unmapped/held without a group, return its blocker; unrelated later same-customer work gets `earlier_hold` and cannot be proposed. Otherwise seed the closure with **its entire compiler group**, then traverse every typed prerequisite and every referenced provider's entire compiler group until fixed point:

- `target`: verify the exact target record and valid original receipt association. Retain the target binding/origin in the witness; do not select its old delivery again.
- `candidate`: require every `providerInputIndexes` reference to resolve to matching compiler-mapped identity, Scope and target ID in this same classification. Include all matching representatives and their groups; never pick an arbitrary winner among competing deliveries.
- `missing`: query the complete mapped index for that exact typed key. No match means `dependency_missing` **in this captured cut**, not absent from the source. If the compiler reported missing but the index contradicts it, fail consistency rather than override metadata. An envelope with the apparent identity but `mapped:null` is diagnostic evidence only, never a provider.

The full-corpus classifier will ordinarily have already joined exact available providers to the same group. The closure walk verifies that fact and retains its proof; it is not a second grouping algorithm. A later invoice in another API stream may join the earliest held allocation; unrelated later groups cannot pass it. Identical candidate economics may legitimately coalesce only if the compiler accepts the entire group. Conflicting same-key providers remain held. Include all coupled candidates, not only whichever events make the seed pass.

Check the full closure count against the approved maximum; no slicing to fit. Use `dependencyOrder` on full typed candidate edges, rejecting cycles/absent references. Topological order is explanatory; do not reorder plan operations or lineage manually. Re-run `classifyBatch` on exactly the selected closure plus its applicable semantic guard events, at the same target/version/asOf. The entire invocation, including semantic guard events and repetitions, must fit the compiler's 1,000 bound. Require accepted financial groups, exhaustive item references and no affecting hold/blocker. The resulting exact plan must represent one complete financial group, or null for a nonempty accepted all-replay group. Do not splice operations or lineage out of the full-corpus plan, which may combine multiple accepted groups.

Return at most one proposed group per subject. Later independent groups for that subject await a new inspection against the actual future target; do not speculate a sequence of commits. A held earliest group produces no proposal for that subject even if another group classifies as valid. Independent subjects may have proposals in the same complete cut while the held group's raw evidence remains unresolved. `financial_replay` still requires original-origin lookup; coalescence refers to the proposed group's new producer and has no invented original receipt.

## Witness and coverage meaning

`SelectionWitness` has an explicit canonical preimage: schema version, source, asOf, exact committed identity/profile/artifact/bundle/manifest hashes, authority observations, per-subject target version/hash, all lane baseline/capture vectors, sorted evidence references/digests, route observations, the complete pre-routing `SourceContractObservation` set with exact binding/consumer/diagnostic references, historical acknowledgment/origin references, and exact classifier bindings plus selected closure/dependency edges. A page reference includes lane/stream/after/next/digest and exact member references. Before hashing, validate actual canonical pages/deliveries and all scalar bindings. Event bytes occur once in the detached internal corpus; witness references resolve to it. Retain validated receipt content or exact immutable receipt references with their digests, and keep the final classification's held/group metadata inside this bounded internal result. No hidden mutable query is necessary to explain why a proposal or blocker was produced. Hashes attest deterministic input integrity, never authorization.

Each `DependencyWitness` names consumer event, the complete accepted typed prerequisite, and either a validated target/origin reference, all captured provider references with group membership, or an explicit no-match over the complete mapped-index hash. Retain the full-corpus group membership and final selected classifier result so a reviewer can see both coupling and financial revalidation. No client-provided witness can be trusted by a future writer.

Coverage labels mean exactly:

| Observation | Meaning | Does not mean |
| --- | --- | --- |
| `complete_captured_cut` | All bounded relevant persisted capture, committed catalog and required history were inspected in one snapshot | Source is caught up, no unseen changes, or any money was applied |
| Subject proposal | Earliest complete group passed captured-cut routing/dependency/classifier checks at the observed target/authority | P1 accepts it, current authority remains active, or commit is authorized |
| Known-independent route | Exact enrolled profile owns the raw identity | Another customer's unresolved event is resolved |
| Raw unknown / held input | Still unresolved in this inspection, with exact evidence | Durable pending/quarantine state or a consumed retry examination |
| Historical acknowledged input | Existing strict receipt/outcome history supports that exact fact | Other positions or other activation baselines are acknowledged |
| Semantic observation | Captured unchanged nonfinancial event validated | Financial application, changed-term approval, or current provider observation |

Report counts only for this explicitly named corpus: distinct delivery routes, proposed financial member occurrences, exact historical acknowledgments and unresolved observations. Keep lane membership counts separate from global delivery counts. Proposed and unresolved counts are not persisted pending/quarantine counters. Do not expose new “applied through,” “resolved through,” lag, percent complete or a source-global financial frontier. Unmapped monetary values remain unknown, not zero; this phase need not expose amount totals.

## Concrete review cases and future proof obligations

These are required implementation proofs, not executed results. Use genuine A5 committed subjects, real accepted capture and isolated PostgreSQL; test-only source producers may supply pages outside the worker. Retain exact vectors/events/classifications/witnesses and before/after storage observations.

1. **Earliest dependency and independence.** Subject A baseline is `a-ledger:10, a-invoices:20, a-semantics:2`; target has payment `pay-1` for 700 cents, original receipt `receipt-A0`, no invoice `inv-9`. Captured `a-ledger:11` is allocation `alloc-1`, 500 cents from `pay-1` to `inv-9`; position 12 is unrelated payment 200 cents. B has its own genuine grant and a valid 300-cent invoice. First cut: A missing exact invoice key, its later payment is not proposed, B's earliest group is proposed. Capture `a-invoices:21` invoice `inv-9` for 900 cents. Second cut: A proposal contains allocation plus invoice, invoice before allocation in dependency order, existing payment origin `receipt-A0`, projected invoice balance 400 cents; unrelated payment remains unselected. No stored money changes in either inspection.
2. **Typed/held providers.** A payment also named `inv-9`, foreign-scope invoice `inv-9`, unknown-account invoice, and invalid/mapping-failed invoice cannot satisfy A's invoice prerequisite. A successfully materialized but financially held provider is included in closure and keeps it held. Two competing invoice deliveries with conflicting economics never yield an arbitrary winner. Identical economics are accepted only by normal compiler coalescence. No invented invoice prerequisite appears on unallocated funding.
3. **Coupling and reversals.** Two allocations sharing payment capacity and a later full reversal remain the compiler's complete coupled group, including existing target allocation edges. A tempting valid subset is not proposed when the full group fails. Direct pure selection tests with genuine accepted classifier outputs cover cycles, malformed provider indexes and over-limit closure; do not claim a cycle fixture is realizable in the current restricted financial DSL if it is not.
4. **Raw routing.** Known seller/account `raw-new` has no grant: exact raw hold remains visible while B is proposed. Missing seller produces a source-wide blocker and zero source proposals. Two apparent profile matches or unrecognized company/seller produce ambiguity/incomplete coverage, not guessed Scope. A paused enrolled A stays mapped and blocked, not unknown. A bundle's unselected profile cannot enroll B. Empty enrollment has the explicit incomplete `no_committed_subjects` representation with no proposals or global-completeness claim.
5. **Payload drift before routing.** A and B are genuinely committed to the same invoice feed/resource and exact approved contract. Keep the declared schema unchanged and capture separately (a) A's invoice with required `amount` renamed to undeclared `gross_amount`, (b) the same renamed field on known-seller unknown account `raw-new`, (c) A's invoice with required `amount` absent, and (d) the same missing field on `raw-new`. For each isolated cut, B's otherwise valid 300-cent invoice is not proposed; retain causing event, exact contract hash/stream/resource, compiler `SOURCE_SCHEMA` and its actual path (`/payload` for the undeclared field, `/amount` for absent required amount), and both affected committed identities. The unknown cases retain their raw unknown route without fabricated Scope. Also cover changed type/material enum and envelope identity mismatch with their actual compiler paths. Positive controls: a structurally valid `raw-new` invoice passes the guard, stays unresolved, and B is proposed; a genuine third committed subject using a separate API feed/resource and independent approved contract is proposed during A/B's mapping block. Its source cut must be complete and its authority/captured semantics valid. A subject using the failed binding receives no proposal through another resource as a workaround. Exercise a non-schema validator early error followed by a later structurally invalid field: it yields explicit incomplete `source_contract_validation`, never a claim that later fields passed. Verify ordinary planner/classifier results are unchanged, guard witnesses are deterministic/bounded, and a missing validator seam fails closed.
6. **History and semantics.** Changed scoped semantic revision followed by matching revision still holds the scope. Unscoped governing change blocks the source. Unchanged semantic input is an observation only. Replays reference exact initial/ongoing receipts; source identity/economic collisions and corrupt origin links fail closed. All-replay proposal has null plan and original receipts, with zero new monetary receipts.
7. **Coverage and bounds.** Distinct approval baseline vectors catch approval-window input independently. Cross-lane canonical conflicts, orphan rows, undeclared streams, unsupported CSV, legacy receipts without supported coverage, uninitialized lane, and cap+1 in each family never produce a complete proposal. Historical incident evidence survives later successful capture. A gap whose closure cannot be proved from retained facts stays unresolved. Bound byte retrieval before parsing, verify timeout cleanup, and distinguish 1,000 retained-input admission from the financial invocation bound.
8. **Snapshot and zero writes.** Barrier-controlled concurrent capture/authority/target commits produce a coherent before or after cut, never mixed reads; repeat at the same fixed persisted state/asOf gives identical witness. A later commit can invalidate freshness without retroactively altering the old witness. Assert unchanged parent snapshots, financial records, imports, receipts, units/outcomes, capture/application heads, pending state, authority and activity. No write SQL/provider/model capability is used. Recreating service/pool rederives the same result from durable inputs; this does not prove durable examinations or dependency release.

The cross-stream fixture must use a genuinely approved API-only multi-stream artifact, not a CSV-bearing Company B lane with its CSV part ignored. If the current source test producer cannot emit this fixture, reserve a narrow test-fixture seam separately; do not alter production source semantics or invent a stream in an already committed manifest.

## Compatibility and the next gate

P1's existing strict contiguous single-stream unit audit, event outcome semantics, heads, receipt tables and runtime001–006 bytes remain immutable. Phase A reads accepted history and does not widen a decoder, reinterpret a field, backfill progress, write another form into `runtime_sync_units`, or pass a multi-stream/noncontiguous selection to P1. Its complete-corpus admission is explicit and independently reviewed; no claim is made that an accepted Phase A proposal meets P1's narrower one-lane/no-foreign-history predicate.

A generalized writer is a distinct future design.
