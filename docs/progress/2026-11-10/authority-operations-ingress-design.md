# Bounded authority operations ingress

Status: **design only; ready for independent review**. No implementation, mounting, migration reservation, machine verification or joint acceptance. Source baseline includes main `cfbf679`, protected inventory repair `cd77775`, accepted current-authority candidate `ad13e2f`, and PR #44 connection reads. This document is the proposed Platform → Experience contract; endpoint names below are not currently available.

## Boundary and approach

Expose authenticated reviewer pause/resume/revoke for one already committed customer through the existing `createCurrentAuthority` service. Reuse its transitions, epoch CAS, immutable command audit, replay and semantic checks unchanged. No activation/reenrollment, general authority resolver, scheduler, capture/apply changes, provider configuration, new financial effects, new policy, or DDL. Runtime006 remains reserved for the separate apply repair.

Authority comes from [PRD §§7,10,19](../../../prdv2.md), freeze [F1/F4/F5/F7](../../superpowers/plans/2026-11-08-contract-freeze.md), the [accepted service plan](../../superpowers/plans/2026-11-09-current-authority.md), [design](../2026-11-08/handoffs/platform-current-authority-design.md), [implementation report](../2026-11-08/handoffs/platform-current-authority-implementation-report.md) and [ad13e2f review](../2026-11-08/reviews/platform-current-authority-ad13e2f-review.md). The accepted plan explicitly requires: “Before opening the mutation transaction, re-invoke the trusted authorizer with the same request and mutation mode, after any awaited observation.” It also says: “WeakMap presence proves only in-process request binding/lifetime, **not continuing session authority**.”

Chosen technical approach: a narrow HTTP adapter and an ephemeral, request-bound control admission ticket. Worker authenticates the control channel, then obtains current session grants from a private control callback at every service admission call. Forwarding a frozen reviewer/grants body would fail the required refresh; forwarding browser cookies/CSRF to the worker would unnecessarily move browser credentials across the boundary. A durable command queue/lease is unnecessary: existing runtime audit already recovers committed results. These are proposed binding choices, not additional product permission rules.

## Experience-facing contract

All routes require the existing server-managed reviewer session; mutations additionally require exact configured Origin and `x-eapr-csrf`. Existing `authorizeReviewer` rejects service/task/operator credential masquerading. The new routes also reject caller-supplied private admission headers. Authentication runs in `onRequest`, before body parsing. No query strings; guarded `IdSchema` account path; mutation JSON body limit 4 KiB; strict objects reject unknown/prototype keys. GET rejects a body and has no automatic HEAD route. All responses use `Cache-Control: no-store`.

| Proposed control route | Request | Success (200) |
| --- | --- | --- |
| `GET /api/connections/:accountId/authority` | No body | Existing `CurrentAuthorityV1` |
| `POST /api/connections/:accountId/pause` | `{expectedEpoch, idempotencyKey}` | Existing `AuthorityStatusResponseV1` |
| `POST /api/connections/:accountId/resume` | Same | Same |
| `POST /api/connections/:accountId/revoke` | Same | Same |

`expectedEpoch` is a positive safe integer; `idempotencyKey` uses existing `IdSchema`. No reviewer, session, grant, scope, source, artifact, bundle, observation, policy, or action property is accepted in the public body; action comes from the fixed route. Public read/result shapes are exactly [current-authority.ts](../../../packages/contracts/src/current-authority.ts): saved identity/pins, source, status/epoch/time, and immutable command result plus `replayed`. They contain no audit session identifier, credentials, protected proof, raw source evidence, or new monetary receipt.

Experience reads authority before enabling actions and retains the exact account/action/body for an unresolved request. It generates a key once per deliberate action and reuses it for retries. A retry must not silently replace `expectedEpoch`, key, account or action. After success, including `changed:false` or `replayed:true`, refetch authority and the existing connection overview. A historical replay result can predate a later revoke; response arrival order does not make it current. Apply current read state only for the same identity and nondecreasing epoch. A 409 stale/conflict requires refetch and a new deliberate action, not automatic reauthorization with a new key. A network/503 failure means outcome unknown; retry the original request with fresh session admission. No unauthenticated command-status lookup or command-history endpoint is added.

The existing `GET /api/connections/:accountId` and `ConnectionStateV1` remain byte-compatible read-only operations views (including inactive/epoch0 and null unmeasured quantities). They do not supply a bundle hash or prove command authority. Only the new authority read enables actions; an inactive/uncommitted account returns 404 there. Show authority-read failure separately from an available overview; do not infer active authority from overview fallback or an initial activation receipt. Keep original `ActivationStateV1` historical. Existing runtime activity remains invalidation evidence, not a substitute for an authoritative read; no new SSE bridge is included.

## Trusted identity and request admission

1. **Control intake.** Authenticate the original Fastify request with `authorizeReviewer(request,{mutation})`, require its account grant, parse/detach the strict request, and retain an immutable operation descriptor `{schemaVersion:'1', accountId, action:'read'|'pause'|'resume'|'revoke', body:null|{expectedEpoch,idempotencyKey}}`. Its canonical hash binds the transport request; it is not authentication. Create a random 256-bit ticket in a module-private map containing only this descriptor/hash, the original reviewer/session identity, and a closure that reruns the existing authorizer on the original request. No exported product mint or generic supplied-authorizer endpoint.
2. **Private worker request.** Use matching `/internal/connections/:accountId/authority` GET and `/internal/connections/:accountId/pause|resume|revoke` POST routes. Send the same public body and ticket in `x-eapr-authority-admission`; send the existing control→worker service bearer separately. Worker validates the bearer in `onRequest` before parsing anything. Strictly parse and recompute the operation hash; only then obtain admission. No caller-provided reviewer or grants JSON is accepted. Authenticated route composition alone creates the opaque request context used by the accepted service; forged or cross-request contexts fail.
3. **Private revalidation.** The worker's injected `TrustedAuthorityAdmission.authorize` calls fixed control `POST /internal/authority-admissions/check` with strict `{ticket, requestHash, mode:'read'|'mutation'}`. A separate supervisor-generated worker→control admission bearer protects this endpoint; do not reuse the source-read token or expose it to web/product tools. Control checks ticket liveness, exact hash and mode, reruns the real session/cookie/origin/CSRF checks, requires the same reviewerId/sessionId as ticket creation and current account permission, and returns strict `{requestHash, grants:{reviewer,allowedAccountIds,allowedSourceRefs}}`. Worker verifies the returned hash and strict grants. Never cache a previous successful callback as refresh. No cookie, CSRF token, arbitrary callback URL, or browser request object crosses processes.
4. **Committed identity.** After initial callback/account admission, worker uses its runtime DB to locate the unique immutable `runtime_activation_imports` scope by the validated globally unique accountId, then calls existing `readStoredActivation(client,scope)` to decode/verify the committed import and its bindings. The lookup scalar alone is not trusted authority. Derive `{scope:stored.activation.scope, activationId:stored.activation.id, bundleHash:stored.bundleHash}` and actual `stored.bundle.manifest.sourceRef`; enforce both actual account/source grants before returning anything. Missing import is 404; corrupt binding is 503. No lookup by latest profile, capture lane, balance, or caller hash. This is an ingress-local identity lookup, not a new general `resolveAuthority` service.
5. **Existing service.** Pass that identity to `read`, or construct the existing strict command with `schemaVersion:'1'`, server-derived identity, route action and parsed epoch/key. Its own initial admission invokes the callback again, validates detached grants, and binds the actual persisted subject. Its refresh callback rechecks the original session after awaited source observation and before mutation, or before concurrent-winner recovery after a failed observation. Exact entry replay receives fresh initial admission and performs no source read. No callback, source read, or control DB access occurs while runtime SQL locks are held. Preserve the service's private WeakMap and awaited cleanup; the HTTP ticket never substitutes for that token.

The small identity lookup releases its client before invoking the service. A5 identity is immutable and unique per account; the service independently revalidates it. This makes the two-field public command sufficient for exact retry today. Reenrollment/version switching would require a separately reviewed API/identity change before mounting that behavior. Occupied key checks remain wholly in the accepted service, including actual-source authorization before replay/conflict. Do not implement a route-side audit shortcut.

### Ticket lifetime, timing and lost response

The ticket exists only while its originating control operation is pending. Delete it in awaited `finally`, on observed caller disconnect/abort, control shutdown, or the fixed HTTP request deadline. It permits repeated matching admission checks during that one request; it is not a one-use nonce because the accepted service deliberately reauthorizes. Bound the map to 256 pending operations; capacity exhaustion returns 503. Proposed transport limits follow existing clients: 8-second control→worker deadline, 2-second worker→control callback deadline, 4 KiB callback request, 256 KiB maximum strictly decoded response, redirects denied, fixed configured loopback origins. These bounds reclaim transport resources; they are not an authority lease or a source-observation TTL.

At each callback, missing/expired/cancelled ticket is 403, missing session is 401, changed reviewer/session identity, loss of required account permission or failed CSRF/origin is 403; the worker also rejects loss of permission for the actual committed source with 403. Unrelated grant-array changes do not reject the request. Malformed responses, callback timeout or unavailable control are 503. Source checks are the existing allowlisted `createSourceSemanticsClient` path. A cancellation before the final callback prevents new admission; cancellation, expiry or session changes **after** its successful final check do not cancel/undo the runtime transaction. As the accepted plan specifies, that check vouches for the short transaction and bounded SQL retries; no continuing callback under locks, cross-DB atomicity, or instantaneous revocation of an in-flight request is claimed. A late commit is resolved by retry with a new ticket and the original command. The same reviewer in a new session can recover it; a different reviewer conflicts at the occupied key. Control restart loses tickets/sessions, never runtime audit/results.

Audit remains runtime004's immutable canonical command + authenticated reviewerId/sessionId + result + successful resume observation. Digest excludes sessionId but includes reviewerId and full command. Never log/persist tickets, cookies, CSRF or service bearers, including request header dumps; redact private transport headers. Real transitions retain existing atomic head/audit/activity publication; no-op/replay emits no duplicate transition activity. There is no control “success” row or mirror that can overrule the worker.

## Errors, composition and dependencies

Return strict existing `ApiError` with safe fixed message, correlationId and empty diagnostics. Preserve `LOCAL_SESSION_*` on public session failures; use existing `AUTHORITY_*` mappings for service/domain errors: 400 INPUT_INVALID; 401 UNAUTHORIZED; 403 FORBIDDEN; 404 NOT_FOUND; 409 IDEMPOTENCY_CONFLICT / STALE / REVOKED / EPOCH_EXHAUSTED / SEMANTICS_MISMATCH (INACTIVE remains a fence error, not a new status); 503 SEMANTICS_UNAVAILABLE / STORAGE_INVALID / UNAVAILABLE. Normalize malformed JSON, oversized/wrong media, extra query/body/header input to 400 after authentication. The control worker-client checks HTTP status against the code allowlist, strict response shape (including result/state identity consistency), requested account, and command action/key/expected beforeEpoch where applicable. Worker ingress verifies the full returned identity and bundle binding against its derived committed identity; control does not independently know that full identity from the public operation. Unexpected status, invalid JSON, wrong binding, oversized result or timeout becomes 503 UNAVAILABLE. Never transform uncertain delivery into success or “not committed.” Authentication also covers Fastify malformed-URL/overlong-path framework errors for these registered routes.

Mount through `featurePlugins` only after design/plan/candidate review. Worker composition needs runtime pool/clock, service bearer, private admission client, and existing source observer; control needs the session service, private admission map/check route and bounded worker client. Do not gate mounting on current activation policy, evaluator pins, candidate eligibility or mutable scope registry. The accepted design says: “Pause/revoke/no-op/replay do not depend on source availability, current operator activation policy files, evaluator artifacts on disk, or newly issued verification.” Registry publication grants no customer permission; current registry removals cannot strand a committed customer in active status. The authority routes use committed scope/source plus current session grants directly. Existing PR #44 overview/parent clients retain their separate registry dependency and may be unavailable while authority operations remain available. Resume alone still needs its accepted current-semantic observation when transitioning paused→active; missing source access does not disable pause/revoke/read/replay. Missing admission wiring fails closed with 503, and must not be presented as an available action by Experience.

**No materially unspecified product permission rule identified for this local-demo boundary.** Authorized reviewers with both current account/source grants may act; there is no added “original approver only” role. The accepted plan's local trusted-control assumption remains: these credentials prove trusted-service/session admission, not a cryptographic human click or defense against a compromised host. Governing-document/schema coverage, future apply's atomic epoch fence, and full V5/V6 acceptance remain independent gates. An external policy that treats scope-registry removal as operational permission revocation is not specified here and must not be invented by this adapter.

## Required verification and ownership handoff

Platform P3 owns the entire authenticated authority ingress: control public routes and worker client, control admission map/callback, worker ingress/identity adapter, callback client and worker composition. Experience owns only safe browser client/UI consumption after this contract is published, not trusted control routes or speculative backend operations. The integrator reserves shared contracts, server framework-error hooks, supervisor secrets and mounting. Exact paths are reserved in the later implementation plan, not by this design. New shared schema exports must preserve protected bootstrap/financial build closure (the `cd77775` lesson); browser imports must stay safe. No DDL is needed.

Required tests before mounting:

- Actual control+worker HTTP/session chain: unauthorized and masquerading credentials, missing/wrong Origin/CSRF, foreign account/source, malformed URL/body/query, actor injection, private-header injection, wrong/missing callback capability, forged/expired/reused-across-operation ticket, response/hash/identity substitution, limits and redacted failures. Reject before unauthorized data exposure or SQL mutation.
- Deterministic resume-observer barrier: invalidate session, remove required account/source permission, switch reviewer/session identity or disconnect before final callback; no command/head/activity commit and no recovered-winner disclosure. Unrelated grant-array changes must not reject otherwise authorized requests. Instrument callback/source calls to prove zero external I/O inside runtime transactions. Document the post-final-admission boundary rather than asserting mid-transaction cancellation.
- Genuine committed A5 fixture: derive exact identity; wrong/corrupt/missing import fails closed; inactive read is 404; missing/mismatched mutable registry or new-activation policy does not block authorized read/pause/revoke/replay; unavailable source blocks only genuine resume. Original activation/receipt/financial rows remain unchanged.
- Lost response after commit and control restart: exact action/body/key under fresh same-reviewer session yields byte-identical result/replayed=true; other reviewer conflicts; stale/no-op/revoked matrix and epoch exhaustion preserve accepted service behavior. Older pause replay after revoke is historical; current GET remains revoked. Verify one audit/effect/activity outcome despite duplicate delivery.
- Experience integration: stable pending command/key, refetch after replay/conflict, no optimistic grant from overview/initial receipt, no authority downgrade from response ordering, connection overview shape unchanged, and correct unavailable/unknown-outcome UI. Typecheck, focused contract/client/route tests, isolated DB/HTTP integration, then bounded browser proof under root's leased configuration. No provider or full-slice success claim.

Independent design review must specifically assess the fresh-admission callback and committed-identity/registry separation before a plan is dispatched. This document publishes a consumable proposal; it does not authorize endpoint mounting or expand the accepted internal service.
