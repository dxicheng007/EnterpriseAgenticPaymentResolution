## Receipt and authority boundaries

The frozen POST body contains only bundle hash and key. The assigned private SELECT over `runtime_activation_imports` can recover scope, request digest and bundle hash without registry access, followed by actual `lookupReceiptAssociation` aggregate decoding. The latter validates canonical persisted request/reviewer/bundle/plan/activation/receipt, stored indexes and approved snapshot. Both queried columns and required app-role reads already exist. Comparing submitted key/hash with that immutable association before any new-application work is implementable without a new public unscoped lookup or schema change. The canonical bundle hash binds its embedded full request and scope; the implementation must retain the handoff's explicit transport-key equality and stored canonical comparisons, rather than accepting a hash supplied independently of the stored aggregate.

Scoped receipt GET can call the existing association reader directly after service authentication and strict scope/hash parsing. Its trust source is the authorized committed intent and stored runtime association, not a fresh current index. This distinction is necessary: A3b's `createParentReadClient` and worker parent/activation readers deliberately resolve the current registry before reads. Reusing those as receipt prerequisites would break the required registry-outage recovery. A5 assigns separate receipt routes/client/repository and explicitly requires immutable recovery, so no incompatible A3b change is needed. Existing A3b activation reads remain the normal scoped inspection path for ALREADY_ACTIVE.

The handoff preserves success-first ordering before current policy, source observation, review head and target freshness. Its post-failure association recheck also handles a peer committing during failed preflight. New-key active-scope checks precede stale-target rejection and are repeated under lock. Pending old intents still require current installed policy and independent source semantics; they are not successful-retry exceptions. Authentication and source/account authorization remain ahead of disclosure at both boundaries. Original reviewer/session/time and committed intent bytes survive authorized recovery without a second grant.
