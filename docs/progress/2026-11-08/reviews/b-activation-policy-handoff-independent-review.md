## Findings

1. **Operator trust and real provenance are implementable.** Preparation derives complete indivisible tuples from immutable registered capture, validated protected descriptor/evidence pin, and fixed build closures. Candidate-policy validation does not install authority: the real A1 reader requires persisted completed provenance and validates registered capture. Explicit operator installation remains separate from control-written artifacts and process startup loading. Empty policies fail despite the shape schema allowing them. Final installation waits for stable closures and fresh proof.

2. **Exact selected-entry validation must remain explicit in implementation.** Actual `financial-attestation-registry.ts` `requirePolicy` searches `policy.entries.some(...)`; its expected argument has artifact, complete profiles, capture and policy, not a selected-profile or evidence-pin parameter. With an aggregate candidate policy, success alone proves membership in some entry. To implement the handoff's existing requirement to validate the exact selected build/capture/pin, compare the returned attestation reservation against the selected entry (and verify the selected profile/scope through the validated descriptor/candidate), or invoke the real reader with a correctly hashed singleton validation policy for that entry. Never invent an extra reader argument or infer per-selection equality from aggregate success. This is a routine implementation of the stated binding requirement, not a new product decision or dispatch blocker. Include a two-entry cross-pin regression.

3. **Protected containment is consistent with actual setup ports.** `readBootstrapExpectation` accepts `{fixtureSetId,fixtureSetVersion,hash}`, full artifact/profiles/manifest/snapshot/events plus registration, and optional roots. Its return includes protected material; only explicitly selected descriptor pins and validated subject/capture digests may leave operator setup. No protected imports belong in the new storage modules, control publisher, worker, or public tools. The proposed private source import follows existing operator setup without changing evaluator exports/build files.

4. **Scope publication has no approval/readiness cycle.** Scope-only selection can publish real immutable identity metadata before eligible financial or target-bound bootstrap proof. Index fields match the actual A0 schema and contain no sourceRef field. Publisher and reader must bind profile/manifest source and scope from the members. Exclusive read-merge-publish locking, retained unrelated entries, immutable history, forbidden account-scope changes and a single captured index/member snapshot give A3b a usable read-only port. The referenced `readStoredTarget(client, scope, snapshotHash?)`, `projectStoredParentView(records, evaluationAsOf)` and `readStoredActivation(client, scope)` exist; they do not themselves create the inactive version-zero state. A3b owns that composition and historical-not-found behavior.

5. **Publication and recovery preserve authority bytes.** Canonical strict-v2 validation, semantic bundle hash checks, immutable no-replace publication, bounded regular-file reads, path/symlink protections and exact repeated-byte comparison cover the proposed filesystem boundary. The configured trusted root is part of the authority boundary; issuer/hash validation alone cannot establish it. Scope current-index replacement and operator policy rotation are intentionally separate from immutable bundle publication. Bundle reads do not impose current policy, preserving later successful-receipt recovery under old authority.

6. **Durable intent adapter matches real contracts.** `ActivationRequest` contains reviewPackageId, expectedPackageHash, expectedArtifactHash, expectedProfileHash, expectedTargetVersion and idempotencyKey. `ReviewerContext` contains reviewerId and sessionId; it has no timestamp or scope. Both are embedded in actual `ActivationBundleV2`. Compare their strict canonical values with the committed-reader return and derive the returned idempotencyKey from that exact request. Do not add invented reviewer/time/request fields. Intent identity comes from the trusted injected reader; authentication, scope authorization and grant linearization belong to A4. A2's seam tests establish transport/recovery behavior only; actual control008 durability remains A4 work.
