### P2 — Wire the model-call trap to the exercised execution boundary, or narrow the claimed proof

Locations: `tests/integration/v5-runtime-isolation.test.ts:168-178`; related `tests/fixtures/v5-ai-off.ts:37-45`, `tests/integration/v5-sync.test.ts:186-214`, and `tests/e2e/v5-ai-off.spec.ts:27-32,53`.

`createModelCallTrap()` is a standalone counter/throwing function. Neither worker activation, capture nor current-authority receives it; it is never installed on a transport or provider boundary. The only calls are explicit self-tests (`trap.call(...)`). Consequently, a real invocation from the exercised worker code would not change this counter or be rejected by it. The isolation test's unchanged counter proves only that the test did not call its helper a second time. Similarly, `page.on('request')` sees browser traffic, not the control/worker Node processes, so `runtimeProviderAttempts === 0` cannot support a worker zero-call claim. The fixture's statement that it throws if anything in the worker path attempts a provider call is false for this wiring.

Required repair: either attach a fail-closed test boundary to actual Node/provider egress for the exercised operations, with a negative probe through that same boundary, or explicitly reduce names/comments/counter assertions to a helper self-test and browser-only network observation and record worker invocation trapping as unimplemented. Do not add a model dependency to production worker code merely to satisfy the test. Keep transport interception confined to the test scope and restore it during teardown. A provider-like Node request through the installed boundary must fail and increment the measured count; actual capture/authority work must produce zero measured attempts.

Basis: PRD local-process boundaries and section 14 zero-call requirement; implementation plan T5.2 requires attempted external model calls to fail in the harness; G5 requires actual isolation evidence. This is a test/evidence correctness issue, not evidence that current production code makes model calls.
