## Concrete source consumers and seams

Existing source `createSourceService(...).getSnapshotRecords(snapshotId)` reads exact snapshot member IDs ordered by stream_id,sequence, and `getSourceCapabilities(sourceRef)` returns SourceDefinition. These are primitives, not authorized discovery tools: callers must prove pinned binding, hashes/contracts and scope. `readDiscoveryCapture({db,store},catalog,{companyId,manifestId})` returns validated CaptureFacts with exact binding/sourceAccounts/evidenceIds and verifies originals outside the owner transaction. `recheckDiscoveryCapture(client,facts)` in composition rechecks exact selected DB content and mutable dossier under FOR SHARE. Preserve these seams and per-call facts; no mutable last-capture cache.

`readEvidence(db,evidenceId,authorize)` returns EvidenceResponse including immutable EvidenceRef, mediaType, original URL/hash/length and located text. It reads stored extraction, not store.get. `readEvidenceBytes` performs blob I/O; tools do not expose bytes, paths or URLs as arbitrary access. `requireCoverage`/`permitsEvidence` enforce company/source and all identities. File documents currently have identities:[] and must be denied for account-only grants, including arbitrary ranges. API citation associations can provide one RawIdentity. Search helper accepts 1..50 but discovery wrapper must enforce 1..20; it searches citation.excerpt, returns `{id,excerpt}`, clips to 2,000 UTF-16 units and preserves surrogate boundaries. Do not claim full-document indexing.

This is a proposed private API, not an accepted wire shape or public plugin extensibility seam. Discovery parses/validates inputs before calling it and validates result again before persistence.

### E1: exact bounded text selection

Given authorized `response = readEvidence(...)`, let `base=response.text.startInclusive`, `spanLength=response.text.endExclusive-base`. Input range is half-open UTF-16 offsets relative to that cited span; omitted range means `{start:0,end:spanLength}`, never whole page/body. Require safe integer endpoints with `0 <= start < end <= spanLength`; reject empty, out-of-range and surrogate-splitting endpoints. Set absoluteStart=base+start and absoluteEnd=base+end, and selected=`response.text.value.slice(absoluteStart,absoluteEnd)`. Return only selected in text.value; output startInclusive/endExclusive are absoluteStart/absoluteEnd in the existing page/body coordinate space; hash UTF-8 selected bytes with existing hashBytes. Check boundaries against original response.text.value and selected.length<=8192. Omitted cited span over8192 returns TOOL_RESULT_LIMIT. A narrow valid range from a longer citation may succeed because no full EvidenceRef.excerpt travels in result. Complete envelope bytecap still applies. Nothing changes document/account authorization: a range is no coverage proof.

### Query position semantics

Order uses existing stream_id lexical then numeric sequence. Restrict to exact pinned snapshot and saved/current authorized task scope, then resource and account filters. afterEventId must belong to that exact current filtered set and means position after that member; unknown/out-of-scope cursor fails. Root explicitly adopts current-query semantics: the ID is not an authorization token or proof of historical filters. No new historical token/state is introduced. nextAfterEventId is last returned ID if more filtered records remain, otherwise null. Reducing page size for bytes preserves this continuation; never skip an oversized next record. Its next request returns TOOL_RESULT_LIMIT and the explicit sticky blocker.

### E2: exact interruption and blocker transitions

| Condition | Persisted transition and scheduling | Recovery/authority |
| --- | --- | --- |
| Owner loss during an otherwise authorized immutable read | Previous generation running read becomes interrupted, not genuinely in-flight; retain same step/dispatch identity and no result/content. Add no sticky semantic blocker solely for owner loss. | Replacement owner may refence interrupted→pending and reclaim under current generation only after current authority, saved ceilings, capture and ordering checks. If run is paused, keep pending without claim until authorized resume. Late old callback cannot settle. No unknown model call is retried. |
| Reviewer pause before claim | Pending stays pending; no new read/model claim. | Existing authorized resume preserves budgets/results and permits later claim only if no sticky blockers. |
| Reviewer pause after claim | Existing current-owner read remains running/in-flight while executing; it may settle fenced result without changing paused run status. If owner is lost, use owner-loss row and cease reporting in-flight. | No subsequent step/model claim while paused. Resume clears no semantic diagnostic. |
| Current authority revoked during claimed read | Transition read running→interrupted with no content and persist DISCOVERY_FORBIDDEN task/run blocker. Interrupted is unresolved, not in-flight. | Sticky: restored policy and pause/resume do not clear blocker or retry this run. Only a new run under restored policy can progress; do not add a clearing endpoint. Authorized historical terminal reads still require current policy. |
| Capture mismatch or oversized single-record/result blocker | Terminal failed step with safe DISCOVERY_CONFLICT or TOOL_RESULT_LIMIT, task/run sticky blocker, no successful content result. Preserve paused status if paused, with diagnostics determining blocked on resume. | New valid run only after cause resolved; owner replacement and resume do not clear diagnostics or reset budgets. |

Current state count uses state='running'; reconcile stale running rows into interrupted/pending under fenced ownership so dead work is never reported as actually in-flight. Interrupted rows with sticky diagnostics stay unscheduled. Owner-loss refencing must not clear any preexisting diagnostics. The current resume API accepts paused and restores blocked when diagnostics remain: preserve it. This increment adds no recovery permission, semantic-blocker clearing, or new endpoint.

Safe codes: DISCOVERY_INVALID for invalid strict input/range/resource/cursor, DISCOVERY_FORBIDDEN for denied selectors, DISCOVERY_CONFLICT for pinned mismatch, SOURCE_UNAVAILABLE for unavailable originals, TOOL_RESULT_LIMIT for oversize, plus existing forbidden/unavailable tool codes. Ordinary typed denied/malformed call results are distinct from sticky authority loss at settlement or capture/oversize failures; do not broadly rewrite HTTP SourceError. Entire-batch semantic rejection fails unresolved batch steps with safe codes and task/run before any child/read success, preserving L2 semantics. No incidental external exception becomes arbitrary persisted text.
