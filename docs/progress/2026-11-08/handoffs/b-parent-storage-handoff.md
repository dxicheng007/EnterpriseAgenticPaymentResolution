## Canonical representation and database shape

Use strict existing parsers, `canonicalJson`, `hashCanonical`, `hashEvent`, `hashPlan`, `hashTargetSnapshot`, and `targetRecordId`. Preserve ordered arrays exactly; only normalize declared sets with existing contract helpers. Store UTF-8 canonical JSON text plus its byte digest wherever exact comparison/recovery matters; optional JSONB projections are indexes, never the source of canonical byte identity. Every read parses, verifies digest and domain hash, and checks indexed columns against parsed fields. A domain hash is not necessarily the digest of the full stored object: retain both where different. No timestamps regenerated during reads or replay. Use explicit bounded BIGINT conversion; never global permissive pg numeric parsers.

The following table names and keys are assigned technical choices, not new wire contracts. Full scope means `(company_id,seller_entity_id,account_id)`; every scoped association carries these columns and references the matching scope tuple. Account ID alone is globally unique but never sufficient authorization.

## Transaction-bound port and lock protocol

Public storage methods accept an explicitly supplied `PoolClient`/transaction handle. They never open their own nested transaction, call COMMIT, perform network/file/model reads, install policy, decide reviewer authorization or retry an isolated write. Use the existing `withTransaction` at the later A5 caller; it retries the whole callback for SQLSTATE40001/40P01, at most three attempts. All locking, rereads, planning and validation must occur again on each attempt.

Required internal ports (implementation may use private helpers, but preserve these responsibilities):

1. `readStoredTarget(client, scope, snapshotHash?)` returns a validated persisted TargetState plus stored hashes, or null for absence. Unknown/foreign requested snapshots never fall back to latest. No sentinel insert or target seed. `projectStoredParentView(records, evaluationAsOf)` is pure, checks legacy references and computes balance using finance while preserving records.asOf/version/hash.
2. `readStoredActivation(client, scope)` returns the immutable paired activation/initial receipt or null; `lookupReceiptAssociation(client, key, expected)` distinguishes absent, exact and conflict using full scope, request hash and bundle hash. Never return a foreign receipt on conflict. A5 additionally compares exact canonical request/bundle bytes when they are available, so a hash comparison does not replace canonical identity checking. Authentication/HTTP errors belong to A3b/A5.
3. `lockFirstImport(client, scope, key)` inserts-or-locks the globally unique scope sentinel, verifies scope, locks existing activation aggregate and target, then rechecks global key association and existing account activation. It returns existing facts for A5's exact-replay/ALREADY_ACTIVE precedence; it does not refresh or replace authority. Global key uniqueness remains the final guard across different scope locks.
4. `lockImportIdentities(client, identities, deliveries)` takes transaction-scoped locks for affected stable target IDs/global economic identities and delivery IDs in one deterministic total order, including absent rows. Use namespaced advisory transaction locks or dedicated immutable key-lock rows; hash collisions may serialize harmlessly, never merge identities. Scope/activation/target locks precede these locks. SQL unique constraints remain mandatory. Existing conflicting bytes or scope fail without rewriting originals. Reads and comparison of existing rows occur after locks.
5. `persistFirstImport(client, lockedContext, validatedImport)` writes the aggregate, metadata/financial records, immutable delivery/economic associations, ordered lineage, approved snapshot/current pointer and transactional runtime activity using the same client. This is a persistence primitive for A5's validated result, never a callable authority grant. Validate parsed bundle/request/reviewer/activation/receipt/plan/targets agree before writes; compare full canonical plan bytes and hash supplied by A5. Reuse `projectBootstrapTarget` and `validateTarget`/`computeBalance` to establish stored effects equal that plan and balances at the explicit plan instant. A5 owns `planBootstrap` recomputation from immutable inputs under these locks and all policy/evidence/semantic eligibility checks.

No generic applyBatch, upsert-record, reset-economics or arbitrary target writer is exported. Exact metadata reuse preserves old bytes and array positions. Projection preserves all prior arrays and appends only actual plan operations; snapshot version advances exactly once per nonempty accepted first import (`0→1` for empty initial state), separately from activation epoch. No empty/ensures-only receipt. Imported target version, snapshot, receipt and original economic ownership must agree before commit. Use existing transactional activity counter/event helper with a schema-valid runtime event; no separate publication transaction.

The persistence primitive must not treat `ON CONFLICT DO NOTHING` as proof of equality. Reread/compare the existing association under locks; abort on any mismatch. Same-key race returns the original successful association to the caller after resolution, never creates a second receipt. Activity, sentinel, record and pointer writes all roll back if any step fails. SQL errors do not authorize a second independently committed transaction or fabricated recovery result.
