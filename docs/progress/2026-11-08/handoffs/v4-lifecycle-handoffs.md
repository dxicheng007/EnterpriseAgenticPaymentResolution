## Proposed internal service seams (not new shared wire contracts)

`ModelClient` exactly follows the proposal: readonly `mode:'scripted'|'live'`, readonly `modelId:Id`, `run(turn:ModelTurnV2):Promise<ModelResultV2>`. Scripts live only in tests. No SDK or keys enter runtime worker. No current cancellation guarantee: invalidating ownership discards callbacks; a timeout does not mean the underlying invocation settled.

`createDiscoveryService({db,clock,modelClient?,readCapture,resolveAuthority})` provides `capabilities`, `startDiscovery(input,authorizedReviewer)`, `readState(runId,authorizedReviewer)`, `pause/resume(runId,input,authorizedReviewer)`. Routes call the actual authorizer first. Proposed trusted `readCapture(companyId,manifestId)` returns validated immutable binding, source subjects and evidence membership; it performs no capture. `resolveAuthority(reviewerId,binding)` reads current server-owned configured reviewer/source/account policy, not a model request or persisted bearer. Revalidate both persisted narrowing and current policy before every new scheduler claim. For this single-local-reviewer application, the composition closure can derive policy from the same reviewer/source/account configuration used to construct the session service; it must reject other reviewer IDs and unavailable/revoked grants. Session expiry is not invented. GET/POST additionally require a current authenticated request, even when replaying an idempotent response.

Source validator must check exact selected company/source/manifest, complete aggregate rather than one stream snapshot, canonical manifest hash, stream/event membership and hashes, aggregate hash, citation identity/binding, and original blob hash availability via existing store.get. Source-owned inspection code should be reused without persisting new capture state. It must not read buildDemoCandidate or final artifact fixtures. Source errors adapt `status` to route `statusCode` consistently. Fail before run creation on missing/corrupt membership; do not silently pick latest. External blob reads occur outside the run transaction; immutable rows are rechecked by exact hashes at insert. If existing source immutability cannot justify this, stop and report the exact race instead of holding a DB transaction over blob I/O.

## State, idempotency and crash protocol

1. Start first authenticates the current mutation request and validates its strict request shape, then checks current reviewer/source authority for the selected source. Look up `(reviewerId,idempotencyKey)` and compare the canonical request. For an existing row, also check current authority against its saved immutable binding: different canonical request yields409; an authorized exact request returns the saved response with zero writes or scheduling even when model configuration has disappeared. Replay does not require capture revalidation or a configured model, never refreshes the saved binding, and never substitutes latest. Revoked source policy rejects replay before exposing the saved response. Only for a new key require a configured model (otherwise503 MODEL_UNAVAILABLE, zero writes), then validate the exact complete capture. One transaction inserts queued run, source investigation, coordinator task and discovery.started. Concurrent identical actor/key resolves the unique winner and returns its saved response; differing request conflicts. Durable actor is reviewerId, not sessionId; a race loser must not replace the winner binding or schedule a second run.
2. Supervisor checks out a dedicated PoolClient, obtains a fixed documented discovery-only session advisory lock, increments generation and reconciles old claims before dispatch. Nonowner cannot schedule. Serialize all owner transactions locally on this client; reads/actions use ordinary pool clients. Consistent locks: run, investigation, task, then activity counter. No model/source I/O inside transaction.
3. Acquire a global in-process four-slot permit before reservation. Under run lock require active owner/current generation, runnable run, current authority, successful dependencies and remaining attempts; persist dispatch, increment attempt/modelCalls and task/run revisions before invocation. Commit, then call model. Release permit only when the underlying Promise settles, including malformed/rejected results. A timeout on a still-reserved dispatch must atomically transition reserved→interrupted on the owning connection under the run/task locks, mark unknown usage once with a durable per-dispatch accounting marker, mark task interrupted, and persist the timeout blocker (run blocked, or paused with that blocker). Increment revisions and publish the allowed interruption summary in that same transaction. Timeout and result acceptance race on the dispatch state: if returned already committed, timeout is a no-op; if interruption committed first, every later callback, even from the same healthy owner, may only settle/release the process-wide permit and must not persist output, add known usage, create tools or clear the blocker. No late-usage reconciliation or replacement call is implemented. Timeout never frees a slot while the underlying call still runs. The semaphore is shared across supervisor replacements within the same process: replacing ownership must not reset slots held by old unsettled invocations. Across process death, uncertain remote calls block their tasks; this is not a live remote concurrency guarantee. Attempt nine may be a no-tool completion turn; ninth tool-bearing result cannot exceed eight rounds.
4. Validate complete ModelResultV2, dispatch identity, configured adapter identity, byte/token limits and all call identities before accepting any step. Accept fresh output only while the exact dispatch remains reserved under the current fence; interrupted dispatches reject it, including same-owner late success after timeout. Persist result fingerprint, usage and all ordered steps atomically on owner client. Same result for dispatch is no-op; changed output/name/arguments conflicts before executing any batch call. Step ID is exactly createToolStepId; native IDs reused in another dispatch produce separate rows. Invalid output consumes attempt, retains trustworthy usage if independently available, otherwise one unknown-call count; no partial tools. Increment toolRounds only once per accepted tool-bearing response. Check bounds before increment; exhaustion fails task, blocks run and records exact counters.
5. Pause locks run and CAS-checks expectedRevision. Once it commits no later model/tool claim is permitted. A still-reserved, non-interrupted model result may persist accounting/pending steps while status remains paused; timeout-interrupted callbacks cannot do so. Pending tool steps do not run. Control-state delegation claim/effect/result is one transaction, so it either wins before pause or is denied afterward. Action replay returns its stored state even after later revisions; caller refetches current state. New stale CAS409 changes no counters/event. A new pause on paused state may return unchanged state; terminal failed/completed actions conflict. Resume only paused runs; preserve every counter/result/blocker and return blocked if any hard blocker remains, otherwise queued/running as scheduler resumes. Pause of blocked work never clears its original causes.
6. Owner error/end invalidates token synchronously, disallows new claims/completions and rolls back/discards owned transaction. Never write a late completion on a healthy ordinary pool connection. Replacement acquires advisory lock and increments generation; old reserved dispatches become interrupted, their attempts remain spent and usage unknown exactly once. Recovery checks the same durable unknown-accounting marker used by timeout; already interrupted/accounted dispatches cannot add another unknown count or interruption event. Tasks become interrupted, run blocked (or remain paused with persistent blocker); old callbacks are fenced out. Committed returned output/steps survive and are not counted unknown merely because tools were pending. Pending unclaimed safe work can be re-fenced to replacement generation under lock; succeeded results never replay. In L1/L2 only delegation has a control effect and is atomic, so no externally uncertain side effect is retried.
7. A reserved-before-call crash is conservatively unknown too: the database cannot prove whether the external call began. Resume does not issue a replacement for an unknown model outcome. Known committed pending output can continue after authorization/fence checks; unknown outcome stays an actionable block. No invented recovery endpoint or unlimited retries. Run `completed` requires current compiled proposal and full blocker assessment in later work; assistant done alone cannot authorize it.
