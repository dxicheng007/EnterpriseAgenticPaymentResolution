## Prepared bytes, fingerprint and head transaction

Capture `HeadToken = null | {packageId,revision,packageHash}` before target/proof/source I/O. Resolve authorization against trusted registered account/source before dependent reads. Read actual parent at manifest.asOf and preserve the full returned recorded state/hash/time. Copy records with `asOf=manifest.asOf` for planning, preserving scope/version/records; hash this planner target separately. The parent snapshot hash and BootstrapBinding.targetSnapshotHash can differ legitimately. Store both bytes/hashes and never rewrite historical parent facts.

The immutable companion stores the ReviewPackage plus exact canonical artifact/profiles/manifest/snapshot/full events or durable immutable references and verified byte hashes; full capture attestation; recorded and planner target bytes/hashes/version; full proposed plan bytes/hash and observed-plan byte hash; exact financial report bytes/hash/attestation; exact bootstrap result ID/hash/bytes; installed policy ID/hash and selected tuple; complete semantic observation; deterministic diagnostics/readiness. Report hash uses exact persisted safe report order, not bundle report-set normalization. Validate full plan operation, event and lineage order; equal balances or planHash fields alone are insufficient.

Ready requires every accepted proposal §6 condition: complete exact capture/profile set/scope, metadata-bearing selected profile, eligible attested mandatory financial coverage, real passed completed exact-target bootstrap, same financial/bootstrap capture and indivisible policy tuple, current actual parent baseline, exactly one nonempty financial baseline, no selected or unresolved source-wide blocker, and current compatible source semantics. Selected keys must equal profile and manifest revisions; governing `*`, missing/mismatched selected keys block, unrelated keys do not. Opaque revisions are compared for equality only. No TTL or cross-database atomic semantic snapshot claim.

Compute fingerprint over all authority-bearing prepared content excluding generated review ID/revision/hash. Include companion associations, full canonical plan/lineage byte hash, both target hashes, proof identities/hashes, policy, capture, scope and diagnostics in deterministic order. Semantic checkedAt remains in audit bytes but is excluded from fingerprint; include sourceRef and exact normalized semantic version map. Repeated observation time alone reuses the existing immutable package and companion, not an overwritten checkedAt.

control008 has a unique account head sentinel with nullable current package pointer and monotonic revision, immutable review/companion rows, immutable proof selections, and immutable intents with a globally unique idempotency key. Store canonical bytes and hashes with scoped foreign keys/uniqueness; app role cannot update/delete immutable rows. Head sentinel insertion plus row lock serializes both absent and present heads. Under that lock first compare the captured null-aware token; stale I/O returns409 (no automatic unbounded retry). Only then return existing package for identical fingerprint; otherwise allocate next revision, hash via existing hashReviewPackage and insert companion/package/head atomically. Never allocate a revision as a substitute for stale-token detection.

GET never prepares or writes. With unavailable dependencies return503 without inventing target, proof IDs, report IDs or a package. Known nonready states may return safe diagnostics; persist a nonready package only when all mandatory ReviewPackage fields refer to real existing facts. Existing ReviewPackage cannot represent a missing report or plan by null: do not add placeholder hashes/IDs or weaken it. This bounded path may simply reject preparation with safe conflict/unavailable diagnostics until real required members exist. The prior head stays historical/current until a valid replacement transaction; new approval always revalidates, so an older ready display cannot bypass changed dependencies.

## Reviewer routes and intent linearization

Keep frozen route names. Add one narrowly scoped prepare trigger because GET must be read-only:

- `POST /api/review/:accountId/prepare`, strict empty JSON body, reviewer mutation authorization/CSRF. Chooses server operator references and runs the above preparation. Returns existing ReviewPackage shape on success.
- `GET /api/review/:accountId`, reviewer read authorization, returns persisted current ReviewPackage; 404 if none. This is a saved review, not fresh readiness proof.
- `POST /api/review/:accountId/activate`, strict existing ActivationRequestSchema only. This is the explicit per-customer approval action. No actor, source URL, scope override, target, plan, report, fixture, semantic observation or readiness fields are accepted.

Reuse `authorizeReviewer(request,{mutation})`; require both allowedAccountIds and allowedSourceRefs against trusted scope/selection (or immutable intent scope/source for an exact retry). Task/service credentials cannot masquerade as local reviewers. Authentication/authorization precedes key lookup and every result. Malformed400, no session401, forbidden403, missing registered resource404, stale/key/binding409 and dependency503; no-store throughout. Local fixed diagnostic strings are sufficient; no authority enum/schema expansion. No correction endpoint is implemented: head-replacement tests use fresh authorized preparation after explicit registered selection change/restart or the internal preparation seam.

For new approval, resolve existing key first. Differing canonical request or scope is IDEMPOTENCY_CONFLICT without leaking the original. Exact existing pending intent reuses its original reviewer/session/time and bundle; do not require the retrying authorized session ID to equal the original or overwrite it. Authorization still applies to the original immutable source/scope. Head correction or current setup outage cannot erase that association. There is no receipt in A4, so do not return replayed:true or success.

For a new key, read current package+companion and exact request/hash/artifact/profile/version bindings. Check authoritative activation read for existing active scope (ALREADY_ACTIVE before stale target). Outside transaction revalidate current registered selection/current installed policy and selected immutable proofs/capture, current parent baseline and a new independent semantic observation. Recompute/compare proposed full bootstrap plan and exact target proof; a changed target requires a new preparation/proof, never mutate old intent bytes. Construct strict ActivationBundleV2 with existing hashBundleV2. Fresh semantic checkedAt can enter the new bundle; normalize/compare semantic versions as above.

Then lock the same head sentinel, recheck key, exact captured token/current package/request/scope, and insert immutable intent with original server timestamp, authenticated ReviewerContext, canonical request bytes/hash, bundle bytes/hash and companion association in one transaction. No filesystem, HTTP, source read or evaluator work inside that transaction. Correction before the lock rejects the stale grant; correction after the committed grant cannot revoke it. Losing same-key requests reread and return the original exact association; conflicting keys fail before overwriting anything.

After commit invoke existing publishIntent. A4 response is HTTP202 with strict local `{state:'pending',reviewPackageId,idempotencyKey}`. It means accepted durable intent only, including when publication must be retried; record safe publication failure internally without changing immutable grant. A crash before the response is recovered by posting the same request: authorize, find exact intent, republish exact bytes, return pending. Expose no arbitrary intent-ID or receipt-key lookup. Use the committed intent reader as the explicit A5 port. A5 will add receipt-first recovery, authenticated worker dispatch, receipt mirroring and authoritative success; A4 must not call a fake worker endpoint or mirror a fabricated receipt. Tests should prove the trusted publisher is inaccessible before the transaction commits.
