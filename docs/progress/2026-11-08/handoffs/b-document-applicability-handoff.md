# Source-owned document applicability prerequisite — implementation handoff

Status: design handoff for root/source-owner acceptance before Sol implementation. No implementation, migrations, source edits, commits, or test execution in this task. Inspected main HEAD `ff0238c194b529c24e4be0c9c0ef6fdf36421be3`; active work may advance it. This prerequisite enables genuine agreement-cited discovery; it does not establish complete V4 success.

## Decision and evidence

Add a private, capture-bound source preparation port that proves **derived association of an exact captured agreement citation with one observed source seller/account tuple**. Initially consume it only for tasks already authorized source-wide. Preserve unknown file read coverage and all existing account-only disclosure denials. Do not append PDF citations to financial events, reinterpret `eventEvidence`, or consume the UI `SourceCoverageResponse` as authority.

The narrow supported source format already has accepted semantics: `docs/progress/2026-11-08/handoffs/guided-discovery-implementation.md`, source reader rules, recognizes the exact A/B full-page agreement grammar, validates IDs and manifest-as-of applicability, and rejects conflicting recognized buyer/name claims and directory contradictions. The orchestration proposal §4 permits a source-owned extractor, but explicitly forbids trusting coverage UI labels. The present gap is the absent trusted producer/consumer port and exact citation binding; it is not missing model competence.

Inspected concrete sources:

- `packages/sources/src/records.ts`: `SourceDefinition` contains company/source/seller, resource contracts, streams. It has no document-to-account catalog or document authenticity rule. `validateSourceEvent` proves the registered event shape and hashes; it does not interpret documents.
- `company-a.ts` and `company-b.ts`: invoice/payment/etc. payloads identify accounts and financial references, not agreement file IDs or document IDs. `sellerEntityId` in the registered source definition is useful as a boundary check; it is not a buyer/account directory. Never infer a missing seller from it.
- `uploads.ts:sourceFileId`, frozen F4 `UploadMetadata`/`ManifestFile`, and `dossier.ts:documentCitations`: immutable company/source/document/version association, bytes, kind, and locator exist. `originalName`, generated `doc-a-*`/`doc-b-*`, file order, and document index have no financial/account authority. Contract ID printed in a PDF is not metadata documentId and must not be joined by spelling convention.
- `scripts/generate-fixtures.ts` A agreement lines 201 onward and B lines 312 onward: explicit seller, buyer, account, legal name and contract ID in each separate agreement. A and B have distinct fee/effective-date ordering. These are public format exemplars, not production dependencies. No protected truth was read.
- `source-coverage.ts`: anchored `agreementFormats`, `parseAgreement`, `parseDirectory`, and recognized conflict checks already encode this narrow source observation. Its `identityPages` selection and aggregate display output do **not** prove complete document exposure. Its code must not simply be imported as an applicability oracle.
- `discovery-reads.ts:readDiscoveryCaptureContents` returns detached original-verified files, exact file citations, events, and unchanged `ValidatedDiscoveryCapture` after member/byte/citation checks and selected-row rechecks. This is the correct preparation seam.
- `discovery-tools.ts:capturedCitations` keeps file identities empty; `eventEvidence` proves API and CSV row associations only. `construction-evidence.ts:prepareFindingEvidence` cannot resolve the agreement ID by scanning events. C2's corresponding per-citation account check has the same limitation.

This proof means: “Under this explicitly supported source grammar, these exact captured bytes assert a contract for this exact raw source tuple, and the recognized identity claims are consistent.” It does not mean the document is authentic, signed, legally effective, financially correct, independently verified, or approved. A hash proves preservation, not authenticity. A fabricated but syntactically valid uploaded agreement must never acquire those stronger labels. The model still authors the profile; the independent evidence/financial/bootstrap gates still establish supported values and readiness.

## Narrow supported set and fail-closed algorithm

1. Validate the caller's server-owned binding and grant just as D1 does. Company/source must agree. For this initial port require `sourceWide:true`; reject account-only calls without returning proof or document details, even if their account matches. Current authorization/dispatch/role fences remain the discovery owner's responsibility before preparation and under its settlement transaction.
2. Resolve the configured catalog entry and read the **requested immutable manifest** through `readDiscoveryCaptureContents`, never latest, the UI coverage route, live upload lookup, or a new capture. Compare all six binding fields to the requested binding. Retain current schema-version validation in D1. Preserve its original-byte hash/length, extraction reproduction, canonical citation, manifest, aggregate, and row-recheck guarantees; do not reimplement them in the new parser.
3. Process the detached complete capture, including all pinned agreement and directory members for conflict detection. Candidate positive documents must be `contract_pdf`, extracted PDF, exactly one page, with a nonempty full-page citation generated by `documentCitations`. Its exact locator must be `{kind:'pdf',page:1,start:0,end:page.length}`. This narrower one-page support is deliberate: the existing display parser's page-one observation cannot justify a mixed/additional-page document. Multi-page documents remain unresolved, including apparently harmless extra pages. Do not concatenate pages, normalize whitespace, use partial regex matches, OCR, or infer content from PDF metadata, names, filenames, indexes, or instructions.
4. Parse that full page with the **existing two exact anchored agreement formats**, after extracting them into a reviewed internal primitive. Validate all parsed IDs with current `IdSchema`, date with `IsoDateSchema`, and retain the existing `effective <= manifest.asOf.slice(0,10)` acceptance condition. Fee/currency/anchor syntax only disambiguates the supported format. Emit no fee, term, interval, due-date rule, financial derivation, or bootstrap defaults. Amount changes within the supported grammar change source hashes but cannot be turned into asserted verified terms by this port.
5. Require the explicit parsed seller to equal the registered catalog seller for these current A/B formats; also require the **exact seller/account tuple** in `facts.sourceAccounts`. Never match just account, name, buyer, or contract ID. Do not create sourceAccounts from document text. A no-event agreement can remain a display observation under existing coverage behavior but is unresolved for this initial discovery port, whose investigations require captured event membership. Cross-seller claims, missing tuple, unsupported format, future/invalid date, mixed account text, extra instructions, or missing exact citation produce no proof.
6. Preserve the accepted recognized identity conflict rule across the complete capture: all recognized agreement claims for a seller/account must agree on buyer and legal name; a recognized A directory contradiction blocks that tuple. A directory may supply several claims for conflict detection, but never gets its own positive single-account applicability proof. Parse all page-one claims needed to detect recognized conflicts, including documents that are themselves unsupported for positive one-page proof; do not let adding an extra page hide a recognized contradictory claim. Unknown prose cannot override a recognized claim or receive a positive association. Do not guess the subjects of unrecognized documents. If such a document is cited, it stays unresolved.
7. Amendment, directory, remittance, arbitrary email/PDF, accountless text, and multi-account documents remain unresolved. No buyer/contract-only join supplies their missing account. Related-evidence labels from coverage are not applicability. Recognized conflicting buyer/name claims block affected agreement proofs. Do not add a new “latest contract wins,” amount disagreement resolution, or contract-ID global uniqueness rule: this port verifies identity association only; conflicting financial values remain the existing construction/verification concern. If a future consumer needs choosing a governing contract, that is a separate specified rule.
8. For a requested supported citation return the exact company/source/capture binding plus evidence ID, file association ID, original hash, complete locator, metadata document ID/version, and derived seller/account. Use `locate` only to check the existing exact citation, not to manufacture a new range. No arbitrary requested substring establishes coverage. Return an explicit unresolved outcome for each requested captured but unsupported citation, never silently drop it. Foreign/missing citation IDs are capture/authorization failures, not unsupported-format successes.
9. Return facts and proof from the same detached validated capture; do no external I/O after deriving a result, no writes, and no source metadata mutation. No proof cache detached from full binding and parser version. The consumer's existing owner-transaction recheck still happens before finding/proposal settlement. No SQL locks across blob I/O and no claim of protection against privileged corruption after validation.

Full original-byte reproducibility proves the extractor's text is the pinned extractor output; it does not prove every hidden graphic, signature, annotation, or other PDF feature was semantically understood. Keeping account-only reads denied is essential. This handoff intentionally does not certify complete exposure coverage even for the supported one-page association.

## Exact private interface

Implement the producer in `packages/sources/src/document-applicability.ts`. Extract only the reusable strict agreement/directory grammar and typed claims into `packages/sources/src/document-identity.ts`; have `source-coverage.ts` consume that primitive without changing its existing wire, parser behavior or coverage semantics. Keep amendment display parsing where it is unless a mechanical extraction is necessary. No export of a raw-text applicability function for discovery callers.

The new source-owned port is separate from the model tool wire, even if carried on the existing injected D1 service object:

```ts
type DocumentApplicabilityRequest = {
  binding: DiscoveryBinding;
  sourceRead: SourceReadGrant; // persisted server context, never model input
  evidenceIds: readonly Id[]; // sorted distinct requested document citations
};
type DocumentAssociation = {
  evidenceId: Id;
  fileId: Id;
  documentId: Id;
  documentVersion: Version;
  originalHash: Hash;
  locator: Extract<EvidenceRef['locator'], {kind:'pdf'}>;
  subject: Extract<DiscoverySubject, {kind:'source_account'}>;
};
type PreparedDocumentApplicability = {
  facts: ValidatedDiscoveryCapture; // unchanged facts shape
  derivation: 'captured-agreement-association-v1';
  associations: readonly DocumentAssociation[];
  unresolvedEvidenceIds: readonly Id[];
};
interface DiscoveryReadTools {
  prepare(input: DiscoveryReadPreparationInput): Promise<PreparedDiscoveryRead>;
  prepareDocumentApplicability(input: DocumentApplicabilityRequest):
    Promise<PreparedDocumentApplicability>;
}
```

All output is private server data. No tool name, model argument schema, browser contract, source capability, new grant, activity payload, database table, or signed attestation is added. The derivation label distinguishes this association rule from UI coverage and is not an authority token. `facts.binding` binds every association; exact original hash/locator/file and metadata are validated against that capture, never accepted from the caller. No legal name, buyer name, terms, raw text, or other-account conflict details need be returned. `source-coverage.ts` may still expose its existing observations independently.

Validate the request structurally at the source boundary with existing schemas. The private producer accepts at most 50 distinct IDs per call and rejects duplicates. A shared C1/C2 consumer helper must first collect the complete required citation set, sort lexically, deduplicate, and split it into batches of at most 50; it must never truncate or change public limits. C1 includes main refs plus every alternative's refs: 50 main refs and ten alternatives of up to 50 refs can yield 550 distinct IDs. C2 includes every citation selected by its accepted requirement matrix below. Validate the exact binding and complete capture facts against the initial preparation on every batch, and validate each batch's complete result partition before merging. Any late-batch failure, malformed result, or unresolved required reference prevents a successful overall applicability outcome; no partial finding/proposal settlement or prefix success is allowed. Every requested ID appears exactly once in associations or unresolvedEvidenceIds. Sort by evidence ID, reject duplicate output IDs, and validate shape/invariants before consumption. Missing/foreign IDs and original/capture corruption retain existing safe `SourceError` classifications; unsupported grammar is a successful unresolved result, not `SOURCE_UNAVAILABLE`. Discovery's wrapper reuses `captureFailure` for thrown errors. Source-wide denial maps to `DISCOVERY_FORBIDDEN`.

Prefer the new mandatory method on the existing service after consumer integration: `createDiscoveryReadTools` already has dependencies/catalog and returns the injected object, so no new app composition dependency is needed. Producer stage may export the separate interface/factory and keep D1's old shape until the serialized consumer patch, or add the unused method without making every old stub implement it yet. The final consumer must never use a permissive fallback when the method is absent. Missing installed support yields unavailable/blocked behavior, not event-independent applicability. Root coordinates the type transition with C2's final interface.

## Exact remaining policy boundary

No new user decision is needed to derive the explicitly printed source tuple from the already accepted supported grammar under the limits above. There is **no existing trusted account binding in upload metadata/catalog/event references** beyond this derived reading, and no general authenticity proof. If the required acceptance standard instead demands authenticated/executed-document provenance, arbitrary-format applicability, or account-only complete PDF exposure, the exact missing choice is the authorized provenance source and rule: for example, an authenticated source document-to-account catalog or an explicit reviewer-established relationship, with its scope, audit/version binding, and revocation/resolution behavior. Current code/specification supplies neither; do not silently introduce one or label the parser output authenticated.

Financial amendment/effective-time selection, clearing old applicability origins, generated parent identity, and preview/verification grants remain separate specified dependencies. This handoff resolves only the ordinary supported agreement citation association prerequisite.
