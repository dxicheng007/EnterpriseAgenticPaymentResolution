## Scope and decision

Mount a fixed, operator-triggered Company A demonstration: introduce the frozen payment/allocation in the source simulator, fetch actual source pages into the accepted durable runtime capture, then run the accepted atomic applier under the existing customer approval. Each operator invocation performs one bounded attempt; it is not a polling scheduler. A retry recovers the original authoritative receipt or retries still-pending captured input. No second reviewer approval is required or manufactured.

Choose authenticated loopback operator HTTP plus a small CLI. The CLI first calls the control-owned source injector and then the worker-owned run-once endpoint. This keeps source mutation in control and financial orchestration in worker and avoids adding a control-to-worker write route exposed through reviewer session. A standalone CLI opening both databases would undermine the process proof; a general polling selector adds deferred scope. Those alternatives are rejected for this increment. This is a routine composition decision under the user's authorization, not a new financial policy.

Frozen facts come from docs/demo/demo-contract.md, not F8 fixtures: local-demo-v1; company-a/legacy-a/seller-a; manifest-a-d22feb38e846-d4e83b7db551 at 2026-10-01T00:00:00.000Z; source account cust-a-d22feb38e846-1; parent account company-a.seller-a.cust-a-d22feb38e846-1; candidate demo-candidate-a, profile demo-profile-a v2 and connector demo-connector-a v1. Runtime hashes must be read from the genuine committed approval and exact registered selection in this namespace. Never hardcode a hash from another setup.

Fixed injection: createScenarioAdmin(dependencies, enabled/token).freshPaymentA(token, {id:'demo-pay-a-cutover-300', accountId:'cust-a-d22feb38e846-1', invoiceId:'inv-a:cust-a-d22feb38e846-1-2026-09-01', amount:'300.00', effectiveDate:'2026-10-03', observedAt:'2026-10-03T00:00:00.000Z'}). Derived source event IDs are evt:pay-a:demo-pay-a-cutover-300 and evt:alloc-a:demo-pay-a-cutover-300; source record IDs omit evt:. Do not confuse event IDs, records, operator scenario ID or receipt ID.

## Existing interfaces and constraints verified in source

- scripts/dev.ts serve('worker') mounts composeWorkerParentReads, composeWorkerActivation and composeWorkerAuthority through featurePlugins. Control localFeaturePlugins creates the evidence store and calls createLocalComposition. Child environments are explicit allowlists, so passing configuration only to the supervisor does not mount it automatically.
- createLocalComposition owns createSourceService(dependencies, localSourceCatalog). Its fetchChanges(sourceRef, streamId, after) returns a validated ChangePage backed by source_events. There is no private feed HTTP reader yet. Source semantics already has a private bearer route and fixed-loopback client, with redirects disabled, timeout and response-size limits.
- createScenarioAdmin is an existing in-process module (not exported from @eapr/sources root); its freshPaymentA writes evidence and both source events idempotently in one source transaction. Use a direct server-only import, as existing fixtures do. Do not reimplement its append logic.
- readIngressAuthorityIdentity(db, accountId) reads and verifies the actual A5 import; it yields identity, sourceRef and pinned hashes. Registry registration alone is not approval.
- createRuntimeCapture({db,clock}).openCommitted(identity) validates the committed baseline, initializes/reopens the lane and returns lane, capturePage(page), readProgress(). It rejects CSV. Capture does not grant current application authority.
- createSyncApplier({db,clock,identity,observe}).prepare(asOf) reads the complete bounded captured suffix, classifier and current target/authority. applyBatch(plan, expectedEpoch) rechecks coverage, semantics and current authority under accepted locks; applyReplay is for new deliveries that are all economic replay. No caller-supplied classifications or plans are trusted by the writer.
- P1 permits precisely one API stream and unchanged semantic capture baseline, one selected customer's full conforming suffix, no extra lane/foreign scope/incidents, and retained history <=1000. It uses a single-statement coverage witness, not a general selector. Preserve that restriction; do not filter a captured page to make it fit.
- readSyncReceipt(client, scope, planHash) validates receipt history, including its unit and origins; readSyncUnit(client, identity, unitHash) validates immutable audit history. Existing runtime_sync_receipts stores plan_hash, full plan and receipt. This is enough to recover the fixed scenario without a new request journal or migration.
- Existing createConnectionReads returns worker-authored ConnectionStateV1 with current authority, captures, initial versus sync receipts, appliedBatches and parent version. Control already proxies it for the reviewer. Parent GET projects current records at explicit asOf; historical snapshotHash remains separately available.

Authoritative reading used: root/apps/packages/parent/db/scripts/tests guides; PRD thesis/process/approval/sync/finance/acceptance; freeze F1/F3/F5/F7 and shared ownership; implementation verification conventions; joint playbook; T0 contract, current board/coordination, team handoff and accepted atomic-apply design. ## Interfaces to implement

It contains frozen identities/scenario/asOf constants, strict empty request schema, and safe source-injection response schema (sourceRef and the two event IDs; no raw evidence, credentials or protected fixture data). Worker successful response reuses ReceiptResponseSchema. No dynamic account, amount, asOf, source URL, artifact, profile, identity, plan or expected epoch is accepted from the operator request.

1. Control POST /internal/demo/company-a/payment, body {}. Enabled only by DEMO_OPERATOR_ENABLED=true and nonempty DEMO_OPERATOR_TOKEN. Constant-time bearer comparison; reject reviewer cookie/CSRF credentials and other service tokens. Invoke the exact existing freshPaymentA call and return only safe identities. Reject nonempty query, extra body fields and invalid transport inputs. It creates source facts, not runtime approval or money. A failure after source commit is safely retryable.
2. Control GET /internal/demo/company-a/changes/:streamId?after=<Cursor>. Only a-finance and a-semantics, legacy-a fixed in code, using the existing separate source-read capability. No arbitrary resource/source parameter. Require exactly one canonical after cursor, no extra keys or body. Delegate directly to the existing createSourceService.fetchChanges. This is a new composition wrapper, not a change to sources package behavior or the public source routes. Source owner should receive an informational interface handoff before release; do not silently edit their modules.
3. Worker POST /internal/demo/company-a/sync, body {}, authenticated with the explicit operator capability, separate from reviewer/session, source-read and ordinary service tokens. It calls createCompanyADemoSync(...).runOnce(). Same enable flag is required. It accepts no source events or monetary plans.
4. CLI npm run demo:inject -- freshPaymentA (existing script currently aliases verify-slice inject). Implement scripts/demo-inject.ts and have only the inject branch of verify-slice.ts delegate to it. Validate the one scenario name; reject all others. Read token from environment, never argv/URL/logs; send {} to the fixed control route, then {} to fixed worker route. Validate both responses; non-2xx, timeout or malformed result exits nonzero and never prints success. Print safe receipt id, replay flag and worker-returned cents. This works after a process restart because injection and apply recovery are durable. A lost response is retried by rerunning the same command.

Keep fixed loopback origins derived from validated local ports; do not follow redirects. Bound body size, response bytes and timeout (source feed may contain a page of 100 events; choose an explicit conservative cap and test it). Authentication must precede body parsing/mutation where supported. Responses no-store; errors expose stable codes rather than SQL, canonical source payloads, stack traces or filesystem paths. Disabled routes must not be advertised as available. Require enabled token differs from service/source/admission tokens in supervisor composition. Never pass it to web, product tools or Discovery. It can be passed to worker/control because those are trusted local demo processes; it is not an authority grant.

## Worker run-once algorithm

1. Resolve only the frozen registered parent account; readIngressAuthorityIdentity must find genuine committed A5. Validate source/company/seller/manifest/profile/connector identity and source-account membership against the stored bundle and registered selection. Values already hash-validated by accepted readers are reused; do not invent parallel cryptographic rules. A registration without import fails closed.
2. Try exact historical recovery before any new apply. In a read-only transaction, query at most two scoped candidate receipt/unit associations overlapping either frozen event, then enforce exactly one coherent pair-only result. Reject partial, extra, multiple or inconsistent associations; an exact-set-only locator is forbidden. Treat SQL results as locators only. Validate the candidate with readSyncReceipt and its actual A5 identity/artifact/scope and exact event-set binding; require its referenced P1 unit through readSyncUnit to check bundle, fixed asOf, lane, receipt/plan identity and the same exact covered-event scenario facts required before new apply. No legacy no-unit fallback. Zero is absent; multiple or partial/conflicting associations are storage error. Return {receipt,replayed:true} only from validated immutable history. No new receipt, progress or activity. Recovery is allowed after pause/revoke, as accepted P1 semantics permit, but request still requires operator authentication. No unvalidated row count or latest receipt suffices.
3. Open the committed runtime capture. Read stored checkpoints. Fetch each declared stream from its own captureCursor (or original manifest resumeAfter supplied by openCommitted), through the private source client. Capture complete pages unchanged; never use injected response events as substitute pages, rewrite sequence, omit unrelated events, rewind a checkpoint, or infer missing members. Empty page indicates drained at the source observation; complete:true alone does not mean exhausted. Bound the attempt to <=1000 fetched events / a finite page count, with explicit error on exceeded bound; do not silently apply a truncated suffix. Source I/O occurs outside runtime transactions. Refresh persisted progress between capture pages so concurrent retries converge; on a conflict fail safely, not spin indefinitely.
4. Call prepare('2026-10-03T00:00:00.000Z'). New work in this demonstration must contain exactly the fixed two source event IDs, have their fixed source/account/effective/observed bindings and the expected payment/allocation semantics. This is a demo-scenario guard, not a new mapping implementation: the compiled artifact and finance still calculate all records/cents. Any additional pending events, semantic capture change, unsupported history, unknown scope, hold or absent plan fails with no application effect. Captured evidence may remain durable. Never skip unexpected input to reach the desired pair.
5. Call applyBatch(prepared.plan, prepared.expectedEpoch). Do not turn stale target, stale epoch or coverage-changed errors into automatic replanning under a new authority. P1 owns allowed SQL retries and recomputation. If concurrent winner committed or response was lost, rerun exact historical recovery, including on SYNC_NO_PENDING. Recovery must not mask a still-unresolved storage error. An unresolved result remains a failure for retry; no claim the event applied.
6. Return the real ReceiptResponse only after commit/recovery. No hardcoded balances; 80000/50000 are test expectations. No all-replay zero-effect receipt is manufactured. A later arbitrary economic alias is outside this fixed scenario mount; accepted applyReplay remains unchanged for its existing callers.

No DDL or modifications to accepted capture/classification/atomic writer/financial behavior are planned. New reader queries and fixed orchestration stay in new worker module. If existing APIs genuinely cannot provide validation, stop and reserve a narrow helper change rather than clone their validators.

## Gaps and stop conditions

No new product/financial decision is required for this frozen fixed scenario. The operator transport, exact evaluation instant and bounded retries are technical choices made here. The full PRD multi-company scheduler and richer measured operations state remain explicitly deferred. A need to accept unrelated events, continue past semantic/foreign-scope blockers, invent expiry/retry/quarantine policy, change approval pins, or support new delivery aliases is a scope expansion, not a reason to weaken P1. Raise that precise gap before changing behavior.

One interface coordination requirement remains: notify source owner of the new composition-only private feed wrapper and Experience of the read-model agreement; do not claim their acceptance before a reply. This design intentionally requires no edit to their source-owned adapters. Independent design review should scrutinize exact-receipt recovery matching and bounded fetch completion before A release; these are implementation correctness concerns, not unresolved financial policy.
