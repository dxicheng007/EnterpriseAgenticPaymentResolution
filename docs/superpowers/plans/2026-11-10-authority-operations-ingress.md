# Authority Operations Ingress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task after fresh independent plan review and root dispatch. Steps use checkbox (`- [ ]`) syntax. Do not dispatch subagents from this task. Root coordinates the fresh independent reviewers and retains composition single-writer ownership.

**Goal:** Expose authenticated reviewer reads and pause/resume/revoke for an existing committed customer through the accepted current-authority service, with fresh request-bound session admission and exact retry recovery.

**Architecture:** Control authenticates the original browser request and retains a bounded ephemeral ticket whose callback reruns that request's real session authorization. Authenticated worker ingress derives the exact immutable A5 identity from runtime storage and calls the unchanged current-authority service; every service admission calls control afresh outside runtime transactions. The adapter neither grants new customer authority nor changes financial records.

**Tech Stack:** Existing Node 24, strict TypeScript, Fastify 5, Zod, `pg`/PostgreSQL 18 and Vitest; existing Playwright for the separately coordinated Experience handoff. No new dependency.

**Spec:** [approved ingress design](../../progress/2026-11-10/authority-operations-ingress-design.md), SHA-256 `53b42ecc85ece726742e76745d20341da0e65e10964a1a4e60b68e0710be1edd`; [design review](../../progress/2026-11-10/authority-operations-ingress-review.md), approved with no unresolved findings. ## Global Constraints

- “Reuse its transitions, epoch CAS, immutable command audit, replay and semantic checks unchanged.” Do not edit `sync/current-authority.ts`, `sync/current-authority-store.ts`, their errors, runtime004, activation, capture or apply implementations.
- “No activation/reenrollment, general authority resolver, scheduler, capture/apply changes, provider configuration, new financial effects, new policy, or DDL.” Runtime006 and parent-storage/apply tests belong to the active apply writer.
- “WeakMap presence proves only in-process request binding/lifetime, **not continuing session authority**.” Tickets never replace real callback authorization or the accepted service's private token.
- “No callback, source read, or control DB access occurs while runtime SQL locks are held.” Release the ingress identity client before entering the service. Final admission vouches for the short transaction and bounded SQL retries; no mid-transaction cancellation or cross-database atomicity is promised.
- “Pause/revoke/no-op/replay do not depend on source availability, current operator activation policy files, evaluator artifacts on disk, or newly issued verification.” Read also requires no new activation setup. Do not route authority through the registry-backed parent/overview resolver.
- Public and private mutation bodies are limited to 4 KiB; the callback request is also 4 KiB. Control→worker deadline is 8 seconds; worker→control callback deadline is 2 seconds; decoded response limit is 256 KiB. Fixed configured HTTP `127.0.0.1` origins only, no redirects. At most 256 pending control tickets.
- “All responses use `Cache-Control: no-store`.” Guarded strict schemas reject unknown and prototype keys; authenticate before body parsing, including recognized framework URL failures. GET accepts no body/query and exposes no automatic HEAD route.
- No tickets, cookies, CSRF tokens or service bearers in persisted records, activity, response bodies, logs or evidence. Worker receives no browser credential, control DB credential, evaluator/model import or model key.
- Platform owns all trusted public/private ingress and clients. Experience owns browser client/UI only. PR #44 overview and original `ActivationStateV1` remain unchanged; no new SSE, command-history or unauthenticated recovery endpoint.
- This document authorizes no implementation, DB/provider activity or mounting. Implementation starts only after fresh plan approval **and** root confirms the active apply writer has released its work. Root reserves shared files and a DB/port lease before the relevant steps.

## Review Focus

- A caller disconnects or the ticket expires while real authorization is awaiting: recheck liveness after the await before returning grants; a normal completed request body must not cancel the ticket (Task 2/4).
- Required source/account permission or actor/session changes during resume: final callback and failed-observation recovery deny commit/disclosure; unrelated grant-array changes remain permitted (Task 4).
- Router rejects an escaped malformed account or overlong path before `onRequest`: the recognized authority route still authenticates before returning a safe 400 (Tasks 2/3/4).
- A committed pause response is lost and its exact retry arrives after revoke or control restart: replay the original result under fresh same-reviewer admission and read current revoked state separately (Task 4).
- Registry/policy files disappear after A5: derive identity from verified immutable runtime import, preserve authority operations, and never mistake a scalar row or overview fallback for authorization (Tasks 3/4).

## Wire and interface decisions

The existing `CurrentAuthorityV1Schema`, `AuthorityStatusCommandV1Schema` and `AuthorityStatusResponseV1Schema` remain unchanged. New leaf exports each schema below with the corresponding inferred type, using existing guarded `strict`, `IdSchema`, `HashSchema`, `ReviewerContextSchema` and safe positive integer checks:

```ts
type AuthorityOperationBodyV1 = { expectedEpoch: number; idempotencyKey: Id };
type AuthorityOperationV1 =
  | { schemaVersion: '1'; accountId: Id; action: 'read'; body: null }
  | { schemaVersion: '1'; accountId: Id; action: 'pause'|'resume'|'revoke'; body: AuthorityOperationBodyV1 };
type AuthorityAdmissionGrantsV1 = {
  reviewer: ReviewerContext; allowedAccountIds: Id[]; allowedSourceRefs: Id[];
};
type AuthorityAdmissionCheckV1 = {
  ticket: string; requestHash: Hash; mode: 'read'|'mutation';
};
type AuthorityAdmissionResponseV1 = { requestHash: Hash; grants: AuthorityAdmissionGrantsV1 };
```

`AuthorityAdmissionTicketSchema` is exactly 64 lowercase hex characters, generated from `randomBytes(32).toString('hex')`; its inferred type is `AuthorityAdmissionTicket`. It is distinct from general `Id`. Descriptor construction detaches parsed input and freezes it before any subsequent await. Hash preimage is exactly `hashCanonical(operation)` for the complete parsed `AuthorityOperationV1`; read includes `body:null`. Map `read` to mode `read`; every other action to `mutation`. Same account but changed route/body/mode is a different operation; hash equality does not authenticate it. Do not normalize epochs, keys or actions on retry.

Public GET `/api/connections/:accountId/authority` returns `CurrentAuthorityV1`; fixed POST `/api/connections/:accountId/pause|resume|revoke` returns `AuthorityStatusResponseV1`, always 200 on success. Matching worker paths start `/internal/connections/`. Only POST body `{expectedEpoch,idempotencyKey}` is accepted. Internal requests carry the ticket in `x-eapr-authority-admission`, with the existing control→worker bearer separately. Callback is only `POST /internal/authority-admissions/check`, protected by the new distinct worker→control bearer. No query or caller callback URL is accepted anywhere.

Preserve fixed `LOCAL_SESSION_*` errors from public initial session checks. Callback translates real session absence to `AUTHORITY_UNAUTHORIZED`401 and session/actor/grant/CSRF/origin denial to `AUTHORITY_FORBIDDEN`403. Missing/cancelled/expired ticket or wrong operation hash/mode is 403. Invalid authenticated syntax/media/size is `AUTHORITY_INPUT_INVALID`400. Preserve the accepted `AUTHORITY_*` status table: NOT_FOUND 404; IDEMPOTENCY_CONFLICT/STALE/REVOKED/EPOCH_EXHAUSTED/INACTIVE/SEMANTICS_MISMATCH 409; SEMANTICS_UNAVAILABLE/STORAGE_INVALID/UNAVAILABLE 503. INACTIVE remains an existing fence error, not a new status. Unexpected transport/JSON/schema/status-code bindings map 503 UNAVAILABLE. Encode strict `ApiError` with request correlationId, fixed safe message, empty diagnostics; never forward an upstream message, diagnostics, stack or correlation identifier as trusted text.
