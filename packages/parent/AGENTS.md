# Parent projection and storage

Follow the [repository](../../AGENTS.md) and [package](../AGENTS.md) guides. [Financial projection](src/state.ts) copies target financial arrays for preview. [Bootstrap projection](src/bootstrap.ts) additionally validates scoped metadata and duplicate IDs, preserves exact canonical matches and rejects conflicting customer, account or billing-configuration records. The read interface supplies a scoped target at an explicit instant. Both are pure; neither persists a parent record, changes target version, issues invoices or moves money.

Use the [bootstrap proposal section 2](../../docs/progress/2026-11-08/handoffs/v3-bootstrap-verification-proposal.md#2-pure-planner-and-projection), [planner handoff](../../docs/progress/2026-11-08/handoffs/b-bootstrap-planner.md), and [financial freeze](../../docs/superpowers/plans/2026-11-08-contract-freeze.md#f3--target-records-mutations-finance-and-preview). Existing metadata arrays retain their order; only declared prepared sets are normalized. Review does not establish factual evidence support.

Run `npm run typecheck` and `npm run test:unit -- packages/compiler/test packages/parent/test packages/finance/test`. Runtime persistence is implemented separately below; authorized activation still requires its assigned worker orchestration and verification.

[Runtime002](../../db/runtime/002_parent_activation.sql) and [persistence](src/persistence.ts), [snapshots](src/snapshots.ts), and [activation store](src/activation-store.ts) retain exact canonical records, scoped metadata, global economic identities, delivery associations, lineage, snapshots and initial receipts. Follow [A3a](../../docs/progress/2026-11-08/handoffs/b-parent-storage-handoff.md) and [review limits](../../docs/progress/2026-11-08/reviews/b-parent-storage-independent-review.md). Reads never seed a target or sentinel. Use the caller's transaction and reacquire every lock inside every `withTransaction` attempt; a lock token identifies a client, not a PostgreSQL transaction. Never reuse it across attempts/pool reuse. A5 must validate authority and recompute the plan under those locks before persistence.

Receipt target IDs are the ordered financial-operation IDs; metadata ensures stay in the full plan/snapshot/lineage. The [registered read service](../../apps/worker/src/parent-reads.ts) resolves one A2 index snapshot per request and projects version zero from registered manifest metadata when the latest target is absent. Both parent and activation GETs use SELECT-only storage reads. First approval and ongoing sync remain separate. Validate changed storage with the focused parent/compiler/finance unit suites and isolated `tests/integration/parent-storage.test.ts`.
