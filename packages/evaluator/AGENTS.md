# Protected evaluator

Follow the [package guidance](../AGENTS.md), [T2.2 plan](../../docs/superpowers/plans/2026-11-08-implementation-plan.md#t22-independently-verify-the-artifact-and-make-the-report-reviewable), and frozen [financial](../../docs/superpowers/plans/2026-11-08-contract-freeze.md#f3--target-records-mutations-finance-and-preview) and [process](../../docs/superpowers/plans/2026-11-08-contract-freeze.md#f6--health-and-protected-verification-protocol) contracts.

- [Reference model](src/reference-model.ts) evaluates complete, independently specified facts at an explicit instant and retains the original financial records for comparison. Keep expected-state calculation independent of compiler, finance, runtime, and subject output. Share contracts and canonical identities.
- [Protocol](src/protocol.ts) and [runner](src/runner.ts) exchange bounded JSON through a fixed Node executable and trusted entrypoint. The subject receives visible inputs only. Keep expected results, protected paths and provider credentials outside the wire and product tool, HTTP and browser roots. Treat runner failure codes as safe transport categories and discard raw stderr.
- [Oracle tests](test/reference-model.test.ts) use public development facts. [Transport tests](test/protocol.test.ts) use scripted children and prove framing and failure handling. A successful exchange establishes structural validity. Report binding, coverage, eligibility and issuance require the separate verification gate.

Run `npm run test:unit -- packages/evaluator/test/reference-model.test.ts packages/evaluator/test/protocol.test.ts` and `npm run typecheck` for this partial oracle and protocol proof.

- [Candidate registry](src/registry.ts) publishes exact canonical bytes before pinning the immutable candidate and capture association in [C003](../../db/control/003_artifacts.sql). Use the control pool and a trusted immutable content root. [Job service](src/jobs.ts) atomically reserves task attempts and commits validated reports with their completion status.
- [Fixture decoder](src/fixtures.ts) and [operator pin store](src/fixture-store.ts) validate private v1 fixture membership and immutable versions. The fixed [launcher](src/launcher.ts) takes a trusted selection of pinned construction metadata and sends only the frozen wire subject to the [evaluator child](src/evaluator-runner.ts). Keep the operator fixture root outside product file and tool roots. Process separation is an additional boundary and requires filesystem access controls.
- [Verification policy](src/verify.ts) binds reports to the job, artifact, manifest, profiles, build, and fixture. The [verification routes](../../apps/control/src/routes/verification.ts) require server-issued reviewer or task authorization. The fixed evaluator exercises twelve financial and capture checks. The private v2 evidence checker can additionally verify supported identity, terms, mappings, and captured planner lineage. The launcher and routes require trusted application composition.
- [Private fixture tests](test/fixtures.test.ts), [subject and report tests](test/verify.test.ts), and [PostgreSQL integration](../../tests/integration/v2-verification.test.ts) exercise public development facts and reviewed generated captures. Run `npm run test:unit -- packages/evaluator/test`, `npm run test:integration -- tests/integration/v2-verification.test.ts`, and `npm run typecheck` for this partial proof.
- [Protected case planning](src/cases.ts) preflights the complete profile matrix before any subject launches. [Independent A/B recipes](src/case-recipes.ts) render the declared F8 facts with the supplied artifact and profile. Captured B reconciles to zero, while its separate synthetic F8 probe starts at 80,000 cents. Planner replay uses a fresh subprocess and supplied prior state. Keep case provenance and expected facts inside the evaluator.
- [Capture boundary cases](src/capture-boundary.ts) compare protected manifest, snapshot and event membership. The evaluator separately counts these validations and real planner executions against each stream's next watermark. These checks cover an in-memory candidate and pinned capture.
- [Evidence support](src/evidence-support.ts) uses validated v2 facts and the observed captured planner outcome. V1, unsupported findings, and configuration operations leave this check unavailable. A valid bootstrap-bearing profile can receive a fresh financial report for its exact subject; that report does not verify metadata ensures or grant bootstrap authority. The check covers financial planner lineage without executing parent configuration.

- [Bootstrap fixtures](src/bootstrap-fixtures.ts), [reference](src/bootstrap-reference.ts), and [cases](src/bootstrap-cases.ts) supply separately pinned protected expectations for the complete import. The [operator](../../scripts/prepare-bootstrap-verification.ts) resolves the exact immutable candidate registration before publishing its sidecar; preserve the separate registered snapshot-object hash and capture content hash. Expected metadata/financial lineage derives independently from validated source facts. Keep these modules out of product and browser imports. Follow [S2](../../docs/progress/2026-11-08/handoffs/b-bootstrap-oracle.md) and the [accepted proposal](../../docs/progress/2026-11-08/handoffs/v3-bootstrap-verification-proposal.md). The dedicated runner is implemented; durable completion registry is implemented separately; activation consumers remain later work.

- [Bootstrap launcher](src/bootstrap-launcher.ts) uses genuine immutable candidate registration and sends protected configuration only on the bounded evaluator fd 3. The [evaluator child](src/bootstrap-evaluator-runner.ts) checks ten real subject cases against the independent oracle and retains the actual observed baseline plan. [Completion validation](src/bootstrap-verify.ts) binds exact request, result, pin and plan bytes. [Private transport](src/transport.ts) is shared with the financial runner but has no generic public package export. Follow [S3a](../../docs/progress/2026-11-08/handoffs/b-bootstrap-runner.md); [Bootstrap jobs](src/bootstrap-jobs.ts) and [registry](src/bootstrap-registry.ts) reserve exact input before launch and persist the actual completion atomically under control005. The restart reader revalidates expected pins/bindings and completed proof. Follow [S3b](../../docs/progress/2026-11-08/handoffs/b-bootstrap-registry.md); readiness and authority still require their separate consumers.

[Financial attestation launcher](src/financial-attestation-launcher.ts) binds a genuine registered complete capture to a protected probe and exact reserved execution. [Protected child](src/financial-attestation-evaluator.ts) evaluates one decoded v2 buffer through [the preserved financial core](src/financial-evaluate.ts), then checks original bytes/build again. Private mismatch frames remain request-bound and redacted. [Safe validation](src/financial-attestation-verify.ts) sanitizes reports before attestation hashing. Legacy numeric-1 protocol remains available; only attested execution enables strict subject-transport failure handling. Follow [A1a/A1b/A1c boundaries](../../docs/progress/2026-11-08/handoffs/b-financial-attestation-handoffs.md); [Registry](src/financial-attestation-registry.ts) and [jobs](src/financial-attestation-jobs.ts) implement durable issuance under control006; see the [reviewed report](../../docs/progress/2026-11-08/handoffs/b-financial-attestation-registry-report.md). [Authenticated composition](../../apps/control/src/financial-verification-composition.ts) now uses these ports through the existing reviewer route; see [A1c review](../../docs/progress/2026-11-08/reviews/b-financial-attestation-composition-independent-review.md). Policy installation and activation remain separate.
