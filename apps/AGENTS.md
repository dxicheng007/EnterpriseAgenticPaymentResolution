# Apps

Follow the [repository instructions](../AGENTS.md) and [PRD local process boundaries](../prdv2.md#local-process-boundaries).

| Area | V0 responsibility |
| --- | --- |
| [Control server](control/src/server.ts) | Own the control pool. Combine its migration probe with a timed, service-authenticated worker health request for `GET /api/health`. Report 503 when either side is unready, with redacted diagnostics. |
| [Worker server](worker/src/server.ts) | Own the runtime pool. Serve authenticated `GET /internal/health` on loopback and probe only the runtime DB. |
| [Browser entry](web/src/main.tsx), [app](web/src/App.tsx), [health page](web/src/features/health/HealthPage.tsx), [proxy](web/vite.config.ts) | Render per-service health and retry through the control API. The browser has no service or database credentials. |

Inject dependencies through the service builders and register assigned feature routes through the existing `featurePlugins` option. Preserve the service boundaries and shared response schemas. Control uses its worker client for worker operations. The worker never connects to the control database or receives model calls, an SDK, or a model key.

The [preview feature plugin](control/src/routes/preview.ts) exposes the frozen preview route when explicitly mounted. It requires an injected read authorizer, immutable source snapshot reader and scoped target reader. Candidate registration is optional and uses the injected registry writer. The [local composition](control/src/composition.ts) reads complete immutable source captures and registers source-derived candidates before preview. Default preview and scoped reviewer GETs use authenticated worker HTTP to read registered parent records. The [parent setup guide](../docs/demo/parent-read-setup.md) explains explicit scope publication and catalog diagnostics. The [verification composition](control/src/verification-composition.ts) uses exact safe pin metadata, control006 or later, the same migrated artifact registry, and the local reviewer session to mount attested verification jobs for registered subjects. The [capture adapter](control/src/financial-capture.ts) validates the full registered capture against visible originals; the fixed protected launcher evaluates exact reserved evidence. Historical jobs remain readable without retroactive provenance. The [operator setup guide](../docs/demo/verification-setup.md) describes how availability degrades independently of source inspection and preview. The evaluator determines eligibility from mandatory coverage and results.

The [local reviewer session](control/src/local-session.ts) uses the configured loopback web origin, an HttpOnly session cookie, and a separate CSRF token for mutations. Loopback HTTP uses this demo-only session for the browser and control process lifetime. Source grants cover the full dossier and its originals. Preview account grants cover only the selected development accounts. The [candidate adapter](control/src/demo-candidates.ts) reads the designated agreement from a captured citation and binds explicit development mappings. Its version 2 profile preserves that agreement's parsed legal name, citation and stable term configuration IDs; historical financial-only profile registrations remain separate. Metadata grants no bootstrap readiness or approval. Starting a session grants no customer approval.

The [activation review composition](control/src/activation-composition.ts) prepares the exact persisted parent baseline from registered capture and protected proofs. The authenticated explicit reviewer action commits a control intent. [Delivery](control/src/activation-delivery.ts) queries the scoped worker receipt first and publishes the canonical intent when the receipt is absent. The [worker activation composition](worker/src/activation-composition.ts) loads its own policy, reads current semantics through the private source capability, and applies the independently recomputed bootstrap under runtime locks. Control mirrors the authoritative receipt. See the [worker setup guide](../docs/demo/worker-activation-setup.md).

## Planned surfaces

- Source evidence, preview and review milestones follow [V1](../docs/superpowers/plans/2026-11-08-implementation-plan.md#v1--inspect-both-acquired-companies-and-their-evidence), [V2](../docs/superpowers/plans/2026-11-08-implementation-plan.md#v2--preview-an-executable-connector-without-writing-the-parent), and the frozen [verification protocol](../docs/superpowers/plans/2026-11-08-contract-freeze.md#f6--health-and-protected-verification-protocol). Agents can request protected verification within their capabilities. They cannot choose expected outputs, fixtures, or runner paths.
- Browser acceptance for [V3 review and activation](../docs/superpowers/plans/2026-11-08-implementation-plan.md#v3--approve-one-customer-and-inspect-the-parent-import) consumes the [trusted activation bridge](../docs/superpowers/plans/2026-11-08-contract-freeze.md#f5--immutable-receipts-and-trusted-activation-bridge). Only the authenticated reviewer route can construct the trusted bundle after checks. The reviewer UI must use the scoped activation read and authoritative worker receipt.
- [V4 build activity](../docs/superpowers/plans/2026-11-08-implementation-plan.md#v4--let-collaborating-agents-construct-the-reviewed-connector) and [V5 connection operations](../docs/superpowers/plans/2026-11-08-implementation-plan.md#v5--keep-the-connection-running-with-no-ai) consume the [durable activity and cursor protocol](../docs/superpowers/plans/2026-11-08-contract-freeze.md#f7--durable-ui-activity-and-cursor-protocol). Activity persists before emission. Replay is ordered per stream and resync follows the frozen high-water cursor sequence.

[Discovery composition](control/src/discovery-composition.ts) mounts capabilities, start, state, pause and resume through the existing reviewer session. It defaults to no ModelClient and no supervisor/poll loop. A new start remains unavailable; authorized saved reads/actions/replay retain their specified behavior. Configured test clients exercise the real durable scheduler and atomic delegation. Preserve source error fields/status, complete pinned capture validation and the mandatory same-transaction SQL recheck. See the [discovery guide](../packages/discovery/AGENTS.md); provider, source read tools, findings/proposals and monitor remain separate tasks.

[Discovery events](control/src/routes/events.ts) mounts as a sibling plugin with the same authorizer and service state reader. Cursor lookup and every stream page/drain enforce current run policy. Per-event cursor IDs are distinct from scan high-water; transport is bounded and closes on authorization or replay failure. Lifecycle retains service-close ownership. Follow the [monitor handoff](../docs/progress/2026-11-08/handoffs/b-discovery-monitor-handoff.md); [Discovery UI](web/src/features/discovery/AGENTS.md) and bounded client are implemented with real-service scripted browser proof; live-model and full V4 acceptance remain separate.
